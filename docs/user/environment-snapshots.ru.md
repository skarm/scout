# Снимки проверенного окружения

[English](environment-snapshots.md) · Русский

Scout сохраняет точное локальное содержимое, которое проверил, и сравнивает с ним
последующие версии. Охвачены skills, плагины, инструкции, конфигурации агента/MCP,
скрипты, зависимости и остальные файлы выбранных корней. Проверяемый код не запускается.

## Начать с обнаружения окружения

Создайте снимок окружения одного агента и проекта. Флаги после `--` относятся
к сканированию, флаги до него — к обнаружению:

```sh
scout discover --agent codex --project /work/project \
  --snapshot /review/checkpoints/project.json -- --format markdown
```

Для Claude Code задайте `--agent claude-code`; `--no-project` выбирает пользовательский
и системный контекст без проекта. Discovery должен завершиться полностью.
Для узкой области используйте `--kind`, `--include-path`, `--exclude-path`.
Снимок записывается в **новый** приватный файл вне расположений агентов и выбранных
входов. Отчёт проверки выводится в stdout; доступны `--output` и `--report FORMAT=PATH`.

После обновления выполните одну команду:

```sh
scout snapshot compare --snapshot /review/checkpoints/project.json --format markdown
```

Scout повторит поиск для сохранённого агента, домашнего каталога и переопределений
конфигурации, проекта, системных путей и фильтров. Новые снимки сохраняют разрешённые
пути и границу поиска по родительским каталогам проекта. Если симлинк перенаправит
сохранённый путь или изменится граница проекта, сравнение с
текущим окружением остановится. `--candidate` сравнивает сохранённые байты, а `--root`
задаёт текущие входы явно. Старые снимки открываются и используют сохранённые аргументы
поиска. Повторный поиск обнаруживает новые компоненты и отмечает исчезнувшие как
удалённые. Неполный поиск останавливает сравнение.

Посмотреть сохранённые аргументы discovery, пути корней и прежний результат без исходных байтов:

```sh
scout snapshot inspect --snapshot /review/checkpoints/project.json
```

Снимок — доверенный файл оператора. Повторное сравнение читает сохранённые пути
или повторяет сохранённый discovery. Проверяйте контекст через `inspect`, если файл
получен от другого человека. SHA-256 обнаруживает повреждение, но не подтверждает автора.

## Явные корни и изменение области

Для отдельных локальных пакетов задайте стабильные ID: `a-z`, `0-9`, `_`, `-`,
от 1 до 64 символов с переносимыми именами файлов.

```sh
scout snapshot create --snapshot /review/checkpoints/manual.json \
  --root skills=/work/project/.agents/skills --root mcp=/work/project/.mcp.json
scout snapshot compare --snapshot /review/checkpoints/manual.json --format markdown
```

Без `--root` сравнение проверяет сохранённые абсолютные пути. Исчезнувший корень
означает удаление; ошибка чтения или вложенный симлинк не считаются удалением.
Такой режим не обнаруживает соседние корни, которых не было в снимке; для этого
используйте discovery либо явно передайте новый набор.

Явные `--root` при сравнении заменяют сохранённую выборку целиком. Пропущенный ID
означает удаление, новый ID — добавление. Сохраняйте ID при переносе содержимого.
`--empty` без корней явно сравнивает с пустым окружением и отключает discovery.
Выбранные декларации не доказывают фактическую активность компонента.

## Что содержит отчёт

Сначала идут общее решение, покрытие и сводка изменений по корням с исходными путями.
Для файлов показаны добавление/удаление/изменение, размеры и краткое объяснение:
инструкции агента, зависимости, конфигурация либо исполняемый исходник. Для небольших
текстовых файлов приводятся размеры изменённых диапазонов строк; это не минимальный diff.
Изменения зависимостей сопровождаются именами пакетов и прежними/новыми версиями.

Обе версии и **оба окружения** заново проверяются одной текущей конфигурацией Scout.
Связи сопоставляются по стабильным ID корней и исходным доказательствам
с сохранением повторов. Новые связи имеют статус `introduced`, сохранившиеся —
`persistent`, не наблюдаемые в текущей версии — `not_observed`. При неполном покрытии
отсутствующей стороны используется `unverified`. Координаты и исходные отчёты обеих
сторон сохраняются. Смена индекса корня при добавлении другого компонента сама по
себе не создаёт новую связь. Совпадение возможностей не доказывает передачу данных
или вызов компонента; `not_observed` не доказывает исправление.

Пересечения описаний сохраняются как связи `skill_description_overlap`.
Scout сравнивает верхнеуровневые поля YAML `description` из захваченных
`SKILL.md`, включая навыки внутри одного корня. Пара попадает в отчёт при
сходстве Жаккара выше 0,5. При сравнении регистр игнорируется, слова выделяются
по Unicode, а частые английские служебные слова отбрасываются. Отчёт содержит
оценку сходства и координаты обоих описаний. В JSON и SARIF оценка хранится
в поле `similarity_basis_points` (10 000 соответствует 100%). Такая связь
указывает на возможную конкуренцию навыков за одни и те же запросы.

Пересечение идентифицируется по стабильным ID корней и относительным путям
к обоим манифестам. Если после правки сходство остаётся выше порога, связь
сохраняет статус `persistent`. Для анализа нужна проверка YAML. Поддерживаются
описания размером до 1 024 байт в UTF-8. Если недоступное описание могло
повлиять на результат, покрытие считается неполным, а отсутствие связи
получает статус `unverified`.

Неизменные корни с полным allow не засоряют текстовый отчёт повторением всей проверки.
JSON сохраняет все отчёты: схема `scout.environment-comparison/v1`, поля `roots`,
`relationships`, `previous_environment`, `environment`, `decision` и `exit_code`.
Вложенные отчёты имеют схему `scout.report/v1`. Для CI выберите `--format sarif`
или добавьте второй отчёт через `--report sarif=changes.sarif`. Результаты SARIF
показывают находки кандидата с привязкой к исходным корням и известным статусом
изменения. Свойства корней сохраняют историю и полноту проверок. Свойства сравнения
содержат обе совместные проверки, изменения связей, решение и код выхода.
Фрагменты `--source-diff` доступны в text, Markdown и JSON.

## Фрагменты исходников

По умолчанию отчёт не содержит строк исходного кода. Для просмотра изменённых
строк явно включите их — они могут содержать секреты:

```sh
scout snapshot compare --snapshot /review/checkpoints/project.json \
  --source-diff --format markdown
```

Это ограниченные фрагменты с удалёнными и добавленными строками, а не применимый
патч. Строки экранируются для терминала и Markdown. Обрабатываются UTF-8-файлы без
NUL размером до 128 КиБ. Общий предел — 400 строк и 64 КиБ; пропуск или обрезка
фрагмента явно помечается и не означает пропуск статического анализа.

## Решения, хранение и лимиты

Создание сохраняет исходные байты и отчёт проверки, включая review/block или
неполный результат. Оно не одобряет находки и не изменяет baseline. Старое решение
не разрешает текущую версию. Изменение содержимого требует как минимум review.
Находки удалённых корней остаются историческими и не блокируют кандидата.

Коды: 0 — полная проверка и allow; 1 — полная проверка с review/block; 2 — неполнота,
неверный вход или ошибка записи. Рассматривайте `decision` и `exit_code` вместе.
Ошибки подготовки или захвата не создают снимок; неполная проверка захваченных байтов
сохраняется с кодом 2. Ошибка захвата указывает проблемный путь и, если сработал
лимит, его значение и единицу измерения. В JSON назначениях она записывается по схеме
`scout.environment-snapshot-error/v1` с полями `operation`, `exit_code` и `problem`.
В `problem` есть `code`, `message`, а при наличии также `root`, `path`, `limit`,
`actual` и `unit`. Ошибки аргументов и подготовки выводятся в stderr.

Снимки содержат **исходные байты**, возможные секреты, пути и контекст discovery.
Защищайте их как исходные материалы. Дайджест содержимого связывает ID корней,
относительные пути, каталоги, байты и executable-биты. При чтении Scout сверяет
хеши и признаки исполняемости файлов в отчёте с сохранённым содержимым. Данные
контекста и отчёт не являются подписанной аттестацией. Scout не запускает
восстановленные файлы, пакеты, hooks или MCP-серверы. Анализ MCP касается
захваченных деклараций.

Лимиты захвата: 1–32 непересекающихся корня, 4096 записей с корневыми каталогами,
глубина 32, путь 512 байтов, файл 4 МиБ, исходники суммарно 16 МиБ, JSON со всем
отчётом 48 МиБ. Бюджеты Scanner применяются отдельно. `--max-changes` ограничивает
каждую пару корней и отдельное сравнение связей; пропуски дают неполное покрытие.

Захват включает все записи выбранных корней. Вложенные симлинки, специальные файлы,
ошибки чтения, конфликтующие переносимые имена, исчерпание лимитов и обнаруженные
изменения во время чтения завершают захват ошибкой. Алиасы самих корней разрешаются
до проверки пересечений. Захват не атомарен: при параллельных писателях зафиксируйте
входы внешними средствами. Владелец, время, ACL и неисполняемые биты доступа не входят
в идентичность содержимого. Фоновое наблюдение не запускается.

## Сохранить проверенного кандидата и сравнить два снимка

Сохраните байты одновременно с отчётом об изменениях:

```sh
scout snapshot compare --snapshot /review/checkpoints/project.json \
  --save-candidate /review/checkpoints/candidate.json --format markdown
```

`--save-candidate` записывает новый приватный файл с теми же байтами и отчётом
совместной проверки кандидата из этого запуска. После просмотра отчёта укажите этот
файл как `--snapshot` в следующем сравнении. Повторный захват для смены эталона
не нужен. Снимок сохраняет решение проверки кандидата, включая review/block
или неполноту. При повторном discovery сохраняется его контекст. Для сохранения
кандидата нужен хотя бы один текущий корень. Файл кандидата и отдельные файлы
отчётов записываются независимо, кандидат публикуется первым.

Чтобы заново сравнить два сохранённых состояния, даже если исходных каталогов уже нет:

```sh
scout snapshot compare --snapshot /review/checkpoints/project.json \
  --candidate /review/checkpoints/candidate.json --format markdown
```

Обе версии берутся из файлов снимков и заново проверяются текущей конфигурацией.
Исходные пути используются для отображения. Сопоставление идёт по ID корней.
Для снимков с разных машин используйте одинаковые ручные ID, если пути discovery
различаются.

## Большие окружения

При сравнении общие бюджеты Scanner делятся между двумя версиями. Например, для
полной проверки пары версий окружения из 2500 файлов недостаточно стандартных
4096 слотов захвата. Передайте через `--config` доверенный файл вне входов:

```json
{"schema":"scout.config/v1","limits":{"max_capture_files":8192,"max_capture_entries":16384}}
```

Бюджеты байтов, операций и остальных проверок продолжают действовать. Пробелы
покрытия дают код 2; успешное создание снимка само по себе не гарантирует полное
сравнение с меньшим бюджетом на версию. Неполнота также возможна из-за границ
статического анализа форматов, контейнеров и кодировок; конкретные причины остаются
в отчёте. Каждый создаваемый снимок проверяется его читателем до публикации.
Если сохранённый ручной путь или его родитель стал симлинком, проверка отклоняется;
для выбора нового назначения явно задайте `--root`.
