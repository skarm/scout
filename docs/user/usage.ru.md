# Использование CLI

[English](usage.md)

Проверьте локальный навык, сохраните отчёт и примените проверенные исключения. Все параметры и лимиты перечислены в [справочнике CLI](../reference/cli.ru.md). Для подсказки в терминале используйте `scout scan -h`.

## Первая проверка

Используйте `scout` из `PATH` или замените его путём к вашему бинарнику. Примеры
работают из любого каталога; пути проверяемых папок считаются от текущего каталога.
Установка описана в [руководстве сборки](../development/native-build.ru.md#установка-и-пути-сборки).

```sh
scout doctor
scout scan ./my-skill
scout scan --format markdown --output /tmp/scout-report.md ./my-skill
scout compare ./previous ./candidate
```

Замените пути в примерах своими локальными папками навыков или плагинов. Проверка
по умолчанию не требует конфигурации и API-ключей и не делает сетевых запросов.
Scout анализирует пакет без выполнения его кода. Сохраняйте отчёты вне проверяемых
каталогов.

Смотрите `Findings` — обнаруженные проблемы, `Completeness` — завершённость
проверки и `Decision` — решение политики: `allow`, `review` или `block`.
`review` возможен и без находок, если ограничения анализа требуют ручной проверки.

Указывайте параметры перед позиционными входами. `--` завершает разбор параметров;
для обычных путей он необязателен. Сохраняйте его перед путём из переменной
или именем, начинающимся с `-`:

```sh
scout scan --format json -- "$target"
```

`scan` принимает до 32 входов; `batch` — другое имя той же команды. `--target-workers` задаёт параллелизм
входов, `--workers` — анализаторов, `--timeout` ограничивает всю операцию.

## Конфигурация

Выберите [готовую конфигурацию](../../examples/configs/README.ru.md) и передайте её через `--config`. Из корня репозитория можно проверить и использовать стандартный пресет.

```sh
scout config validate --config examples/configs/standard.json
scout scan --config examples/configs/standard.json ./my-plugin
```

Флаги переопределяют конфигурацию. Неуказанные поля получают значения по умолчанию. Scout отклоняет неизвестные и повторяющиеся ключи. Храните конфигурацию, baseline, правила и кеши вне проверяемых входов.

## Сохранение отчётов

```sh
scout scan --format json \
  --report json=/ci-results/scout.json \
  --report sarif=/ci-results/scout.sarif \
  --fail-on high --timeout 2m ./skills ./plugins
scout scan --format markdown --output /ci-results/scout.md ./my-plugin
```

Форматы: `text`, `json`, `sarif`, `markdown`. Без `--output` основной отчёт идёт
в stdout. Повторяемый `--report FORMAT=PATH` добавляет другие представления.
Диагностика идёт в stderr. Создайте каталоги отчётов перед запуском.

Текст и Markdown показывают решение, находки, пробелы и сведения о проверке. Отчёт сравнения показывает новую версию первой и отдельно учитывает её находки. JSON и SARIF сохраняют стабильные идентификаторы и машинно-читаемые доказательства.

Для UTF-8-файлов с меткой порядка байтов (BOM) SARIF исключает её из текстовых колонок и использует байтовые смещения для областей, захватывающих её. Scout сохраняет исходные координаты и указывает `utf8_bom: true` в метаданных файла.

Scout готовит каждый отчёт в приватном временном файле, затем заменяет назначение
переименованием. Ошибка подготовки сохраняет прежний файл. Символические ссылки, каталоги и пути
внутри проверяемых входов отвергаются. Отчёт также не может занять имя отсутствующего
входа, включая алиасы регистра и Unicode на его файловой системе.
Несколько файлов публикуются независимо.

Коды завершения:

- `0`: полный запуск, политика разрешает установку, все отчёты записаны.
- `1`: полный запуск, политика требует ручной проверки или блокирует установку.
- `2`: неполный, неуспешный или отменённый запуск; неверный запрос; ошибка записи.

В CI сохраняйте отчёты и исходный код завершения. Консервативная область проверки
также требует ручной проверки при заявленных ограничениях языка.
См. [выбор области](inspection-profiles.ru.md#область-проверки).

## Baseline

Создайте baseline из JSON-отчёта с одним входом, проверьте записи и одобрите их:

```sh
scout baseline create --from /ci-results/scout.json \
  --output /ci-results/pending-baseline.json \
  --reason 'Manual triage required' --expires '2099-01-01T00:00:00Z'
scout baseline approve --from /ci-results/pending-baseline.json \
  --output /ci-results/reviewed-baseline.json \
  --reason 'Reviewed by operator' --expires '2099-01-01T00:00:00Z'
scout scan --baseline /ci-results/reviewed-baseline.json ./my-plugin
```

Задайте будущий срок в RFC3339. `create` сохраняет неодобренные записи. `approve` одобряет все записи, пока выбор не ограничен повторяемым `--fingerprint SHA256`. Для предварительного просмотра одобрения или продления используйте `--dry-run`. `renew` продлевает одобренные записи и по умолчанию сохраняет обоснования. При изменении идентичности нужна новая проверка. Исключения по маске требуют `--allow-baseline-globs`. Находки, пробелы и семантические гипотезы остаются в отчёте. [Флаги baseline](../reference/cli.ru.md#baseline)

## Сетевые сервисы и дополнительные rules

Сетевой вход требует `--allow-download`. Для URL Git-репозитория также нужен
`--revision` с полным SHA коммита. См. [внешние источники](../reference/external-sources.ru.md).

```sh
scout scan --osv --format json ./my-plugin
scout scan --osv --allow-osv-network \
  --format json ./my-plugin
scout scan --osv --osv-cache /ci/osv-cache.json \
  --osv-cache-max-age 168h --format json ./my-plugin
```

OSV проверяет точные координаты захваченных зависимостей. `--osv` сам по себе
включает встроенную подборку без сети. Scout также использует её для совпадений,
если разрешённый сетевой запрос и кеш оператора не дали пригодного ответа.
Подборка покрывает отдельные стабильные релизы npm, PyPI и Go. Scout сохраняет
источник находки и помечает покрытие таких координат как неполное.
Запись об уязвимости не доказывает её достижимость в проверяемом коде.
[Источник встроенных данных](https://github.com/github/advisory-database)

### Известные вредоносные зависимости

Доверенный кеш с `"version": 2` включает `MAL001`. Точные координаты зависимости с классификацией `malicious-package` дают находку Critical с доказательством из захваченного манифеста или lockfile. Обычные уязвимости проходят по `OSV001` (High). Префикс `MAL-` в идентификаторе сам по себе не задаёт классификацию.

Используйте `--osv --osv-cache FILE` и храните кеш вне проверяемого входа. Подставьте проверенные данные и фактическое время запроса.

```json
{
  "version": 2,
  "queried_at": "2026-11-03T12:00:00Z",
  "records": [{
    "ecosystem": "npm",
    "name": "sample",
    "version": "1.2.3",
    "vulnerabilities": [{
      "id": "MAL-fixture",
      "kind": "malicious-package",
      "modified": "2026-11-03T11:00:00Z",
      "source": {
        "name": "operator-intel",
        "url": "https://example.invalid/intel/MAL-fixture",
        "revision": "snapshot-1"
      }
    }]
  }]
}
```

При подготовке кеша проверьте классификацию и запишите точные экосистему, имя и версию. Для вредоносной записи обязательны `source.name`, `source.url`, `source.revision` и время `modified` в RFC3339, не позднее `queried_at`. Имя и ревизия ограничены ASCII-токенами. Используйте HTTPS URL без учётных данных, запроса и фрагмента. Scout сохраняет сведения об источнике, заявленные оператором, без обращения по URL и проверки подлинности.

Пустой массив `vulnerabilities` означает проверенное отсутствие записей обоих видов. Пропущенные или устаревшие ответы и неизвестные версии оставляют пробелы. При разрешённой сети свежий кеш версии 2 имеет приоритет. Обычные сетевые ответы могут добавить уязвимости для пропущенных координат, но оставляют `classification_not_cached` и не экспортируются как завершённая классификация.

Лимиты кеша: 256 КиБ, 4096 координат и 4096 записей на координату. Отчёты сохраняют сведения об источнике и SHA-256 кеша. `osv.Export` сохраняет версию, проверенные отрицательные ответы и время запроса. [Флаги OSV](../reference/cli.ru.md#уязвимости)

### Версионируемые наборы правил

Чтобы добавить YARA-правила, используйте доверенный локальный пакет `scout.rulepack/v1`. Он хранит ID, версию, ABI и хеш исходника. Держите пакет вне проверяемых входов.

```sh
scout rules pack create --id team/agent --version 1.2.3 \
  --yara /ci/agent.yar --output /ci/agent-1.2.3.rulepack.json
scout rules pack inspect --sha256 "$trusted_sha256" /ci/agent-1.2.3.rulepack.json
scout scan --rulepack /ci/agent-1.2.3.rulepack.json \
  --rulepack-sha256 "$trusted_sha256" --format json ./my-plugin
```

Задайте `trusted_sha256` хешем пакета в нижнем регистре из доверенного процесса выпуска. Хеш проверяет все байты пакета. Доверие к издателю устанавливает процесс выпуска. Для обновления или отката меняйте путь и хеш вместе. Работающий Scanner сохраняет загруженный исходник.

В конфигурации используйте `signatures.rulepack_file` и `signatures.rulepack_sha256`. Профили standard и review включают YARA. В custom добавьте `--checks yara`. Выберите один способ загрузки: `--rulepack` или `--yara`.

Создание и просмотр работают без YARA-X. При сканировании Scout компилирует исходник до захвата. Неподдерживаемый синтаксис, повторяющиеся имена, include и console завершают операцию ошибкой. Лимит пакета и исходника составляет 256 КиБ. Отчёты сохраняют метаданные и хеши пакета. [Флаги rulepack](../reference/cli.ru.md#пакеты-правил)
