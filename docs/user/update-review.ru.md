# Сравнение обновлений

[English](update-review.md) · Русский

`compare` заново сканирует две локальные версии одним Scanner и сравнивает
наблюдаемое содержимое. Находки обеих сторон сохраняются; политика учитывает
все находки кандидата.

```sh
scout compare --profile standard --format markdown ./previous ./candidate
scout compare --profile standard --max-changes 4096 \
  --format json --output /ci-results/update.json ./previous ./candidate
```

Обе копии подготавливает оператор. URL и настройки загрузки отвергаются.
Общий тайм-аут охватывает оба сканирования и сравнение.

## Сравниваемые изменения

- Файлы сопоставляются по относительным путям; два одиночных файла занимают общий слот.
- Элементы извлечённых архивов сопоставляются по именам, другие преобразования — по родителю и порядковому номеру.
- Компоненты сравниваются как мультимножества, без угадывания переименований безымянных обработчиков.
- Зависимости сравниваются как декларации, без вывода об установленных версиях.
- Находки сопоставляются по проверке и точным доказательствам; дубликаты сохраняются.
- Сигналы изменений манифеста отражают выбранные изменения деклараций и разрешений.

Статусы находок: `introduced`, `relocated`, `context_changed`, `not_observed`
и `unverified`. `not_observed` не доказывает исправление. Неполная проверка
или недоступный объект дают `unverified` для затронутого сравнения.

## Решение и вывод

Блокировка кандидата сохраняется. Неполнота любой стороны или сравнения исключает
allow. Изменённое содержимое требует ручной проверки даже без новых находок.
Полностью проверенные одинаковые входы могут получить allow по выбранной политике.

JSON сохраняет роли обеих сторон и `run.comparison`. SARIF содержит отдельные
запуски для каждой стороны. Text и Markdown показывают изменения и результаты входов.
См. [запись отчётов и коды завершения](usage.ru.md#сохранение-отчётов).

`--max-changes` по умолчанию равен 4096, допустимо 1..20000. Пропуски из-за лимита
делают сравнение неполным, но не удаляют находки. Семантическая проверка требует
согласия на передачу исходников обеих версий.

В Go используйте `Scanner.Compare` со `scout.DefaultCompareOptions()`.
См. [контракты API](../development/go-api.ru.md).

## Эталонные снимки MCP

Импортируйте уже захваченные результаты MCP локально:

```sh
scout mcp snapshot --source-id production/catalog-readonly \
  --output ./reference/server.mcp-snapshot.json ./capture.json
scout mcp snapshot --source-id production/catalog-readonly \
  --output ./candidate/server.mcp-snapshot.json ./new-capture.json
scout compare --profile standard --format json \
  ./reference/server.mcp-snapshot.json ./candidate/server.mcp-snapshot.json
```

Вход содержит результат `initialize` и результат `tools` с объединённым списком
инструментов. Используйте тела результатов, без обёрток запросов и ответов JSON-RPC:

```json
{
  "initialize": {
    "protocolVersion": "2025-11-25",
    "serverInfo": {"name": "catalog", "version": "1"},
    "capabilities": {"tools": {}},
    "instructions": "Read the product catalog."
  },
  "tools": {
    "tools": [{"name": "lookup", "inputSchema": {"type": "object"}}]
  }
}
```

Импорт отклоняет повторные ключи и имена инструментов, некорректный Unicode,
отсутствующие обязательные структуры, любой `nextCursor` и `resultType`, отличный
от `complete`. Предварительно объедините все страницы. Лимиты входа и снимка:
256 КиБ, 32 уровня JSON, 8192 узла и 256 инструментов. Серверы и инструменты не
запускаются, ссылки схем не загружаются; семантика JSON Schema не валидируется.

Поля `name` и `version` в сведениях о сервере обязательны и имеют строковый тип;
пустые значения сохраняются как отображаемые метаданные. Идентификатор источника
и имена инструментов остаются непустыми.

Оператор проверяет и защищает эталонный файл, затем явно выбирает его как `before`.
Создание снимка не означает одобрения и не подавляет находки. Идентификатор источника
должен различать сервер и контекст авторизации; одного `serverInfo.name` недостаточно.
Метка задана оператором и не доказывает удалённую идентичность или полноту списка.
Снимки содержат импортированные описания и схемы; храните их как исходные материалы.
Отчёты сохраняют хеши и координаты доказательств вместо значений.

JSON `run.comparison.mcp_changes` показывает добавленные и удалённые инструменты,
изменения инструкций, версии протокола, сведений сервера, capabilities, заголовков,
описаний, входных и выходных схем и annotations. Прочие поля протокола фиксируются
группами extensions. Имена сопоставляются по хешу с учётом регистра. Порядок списка
инструментов и ключей объектов не создаёт MCP-различий; порядок прочих массивов
сохраняется. У изменения есть ссылки на исходные байты снимков. Смена идентификатора
источника, повреждение или недоступность снимка оставляют сравнение непроверенным.
MCP-изменения разделяют `--max-changes` с остальными различиями и требуют review.

MCP-различия сохраняют общий статус проверки. Существующие ограничения покрытия
JSON extraction делают полный scan неполным (код 2), даже если выбранные MCP-поля
сравнены полностью или не изменились. Рассматривайте полноту сравнения и MCP-различия
отдельно: неизменные объявления не доказывают безопасность сервера или инструментов.
Изменение только форматирования байтов также может требовать review по существующей
политике сравнения файлов.

Поля соответствуют выбранным структурам [спецификации MCP tools](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/2026-07-28/docs/specification/2026-07-28/server/tools.mdx).
