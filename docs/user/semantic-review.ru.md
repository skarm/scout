# Семантическая проверка

[English](semantic-review.md) · Русский

Семантическая проверка передаёт выбранные фрагменты исходников настроенному
LLM-провайдеру. Она добавляет гипотезы и оценки, сохраняя статические находки.

## Включение

Для настройки через файл скопируйте и заполните
[review.template.json](../../examples/configs/review.template.json) по
[инструкции пресета](../../examples/configs/README.ru.md#шаблон-llm-проверки).

```bash
scout scan --profile review --semantic --allow-source-upload \
  --llm-provider chat-completions \
  --llm-endpoint https://trusted.example/v1/chat/completions \
  --llm-model YOUR_MODEL --llm-api-key-env REVIEW_API_KEY \
  --timeout 3m --format json ./my-plugin
```

Задайте доверенный адрес сервиса, модель и переменную с учётными данными. Адрес в примере —
заполнитель. Передача требует явного согласия: исходники могут содержать секреты,
полное удаление которых не гарантируется. Для HTTP нужны числовой loopback-адрес
и `--llm-allow-loopback`. Локальный сервис тоже может пересылать запросы наружу.

Поддерживаются Chat Completions, Anthropic Messages, `anthropic-proxy` для Vertex
и выбранные формы запросов Bedrock Messages. Bedrock требует явно заданных региона
и переменных с учётными данными AWS. Автоматического поиска учётных данных
на компьютере или в проверяемом пакете нет. Перенаправления, повторные запросы
и переключение провайдера отключены.

## Режимы

- `discovery`: независимый поиск по фрагментам исходников.
- `intent`: сопоставление назначения и наблюдаемых возможностей.
- `tool_consistency`: сопоставление деклараций инструментов с кодом одного пространства имён.
- `assessment`: оценка каждой сохранённой статической находки.
- `proposal_assessment`: повторная проверка гипотез по исходным доказательствам.
- `quality`: дополнительные критерии качества и политики; включаются через `--quality-review`.

Оба прохода используют общие лимиты запросов и входа. По умолчанию допускается
до 64 запросов на вход, 2 МиБ сериализованных пользовательских запросов на весь
запуск и 30 секунд на запрос. Действует и общий бюджет сервисов: по умолчанию
64 запроса, разделённые между входами и включёнными сервисами.
Системные инструкции, схемы и оболочки провайдера не входят в лимит байтов входа.

Лимиты семантической проверки меняют параметры `--llm-*`. Общий бюджет сервисов
задаёт `limits.max_service_requests` в файле конфигурации; отдельного CLI-флага нет.
`--timeout` ограничивает всё сканирование.
Пропущенные задания и некорректные ответы оставляют пробелы проверки.

## Результаты

Ответ должен ссылаться на выданные сканером фрагменты текущего запроса.
Локальная валидация отвергает неизвестные коды причин, чужие ссылки и некорректные ответы.
Отчёт сохраняет проверенные классификации, хеши и координаты, без произвольной
модельной прозы и фрагментов исходников. Согласие модели не разрешает установку.

Протокол описан в [инструкциях проверки](../reference/validation-pack.ru.md),
интеграционные тесты — в [проверке знаний](../reference/knowledge-runtime.ru.md).
