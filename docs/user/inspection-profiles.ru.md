`scout profiles` перечисляет профили, `scout capabilities` показывает доступные
движки. `scout config validate` проверяет конфигурацию до чтения входа.

## Что встроено

Полная сборка с профилем `standard` выполняет следующие проверки без сети
и без установки дополнительных сканеров:

- **Инструкции агента:** попытки переопределить системные правила, скрыть действия
  от пользователя, раскрыть привилегированные промпты, передать секреты или закрепить
  инструкции в памяти для будущих сессий.
- **Конфигурации навыков, плагинов и MCP:** обход подтверждений и песочницы, широкие
  разрешения, команды хуков жизненного цикла, незакреплённые версии пакетов запуска,
  открытый HTTP и чувствительные данные в декларациях.
- **Код и потоки данных:** выбранные операции запуска команд, `eval`, чтения
  секретов, передачи данных в сеть, небезопасной десериализации, построения SQL
  и отключения проверки TLS. Есть проверки Go, Shell, JavaScript/TypeScript,
  Python и SQL; покрытие различается по языкам.
- **Литералы учётных данных:** маркеры приватных ключей и выбранные форматы токенов
  GitHub, GitLab, Slack, Stripe, OpenAI и Anthropic во всех захваченных файлах,
  включая скрытые файлы, документацию и бинарные потоки. Эти проверки работают
  без сети и не проверяют, действуют ли найденные учётные данные.
- **Зависимости и состав пакета:** подмена источников пакетов, локальные замены
  модулей Go, автоматический запуск при установке, непроверенные локальные
  компоненты и непрозрачные исполняемые вложения.
- **Скрытое содержимое:** HTML-инструкции, выбранные управляющие и визуально похожие символы Unicode,
  NUL и несоответствия содержимого подсказкам имени файла. Поддерживаемые вложения
  распаковываются или декодируются в пределах лимитов и тоже проверяются.
- **Инструменты:** коллизии идентификаторов, подозрительные описания и параметры,
  сочетания доступа к чувствительным данным и сетевых возможностей.
- **Адаптированные правила SkillSpector:** дополнительные шаблонные и структурные
  проверки внедрения инструкций, доступа к секретам, полномочий, инструментов
  и цепочки поставки.
- **Встроенные YARA-X-сигнатуры:** вредоносное ПО, веб-шеллы, майнеры, инструменты взлома,
  угрозы в навыках агентов и составные правила, адаптированные из Cisco skill-scanner.

JSON разбирается встроенными средствами; полная сборка также включает Tree-sitter
для Python и JS/TS, парсеры YAML/TOML и движок YARA-X. Сокращённая core-сборка
не содержит полного набора нативных движков и требует явного профиля `custom`.
Разбор синтаксиса сам по себе не является проверкой всех возможных действий программы.

Посмотреть идентификаторы, описания, методы и ограничения правил:

```sh
scout rules list
scout rules list --all
scout capabilities
```

`rules list` показывает базовый каталог; `--all` добавляет описания адаптированных,
Python- и YARA-проверок. Это каталог возможностей, а не список реально выполненных
проверок: выбранный план, применимость и результаты отражаются в отчёте.
Границы анализа описаны в [поддержке языков](../reference/languages.ru.md),
происхождение наборов — в [источниках адаптаций](../reference/port-manifest.ru.md).

### Проверки токенов провайдеров

Эти встроенные проверки работают и в сокращённой core-сборке:

- `SE002`: выбранные GitHub PAT, OAuth, user, refresh и прежние installation tokens.
- `SE003`: токены GitLab со стандартным префиксом `glpat-`.
- `SE004`: выбранные bot и user tokens Slack.
- `SE005`: секретные и ограниченные ключи Stripe live/test; публичные ключи исключены.
- `SE006`: выбранные форматы project, service-account, admin и прежних ключей OpenAI.
- `SE007`: выбранные форматы ключей Anthropic `api03` и `admin01`.

Правила проверяют границы токенов и отфильтровывают известные заглушки. Они анализируют исходные байты и поддерживаемые декодированные представления. Лимит составляет 65 536 кандидатов на правило для одного представления. Превышение оставляет пробел. В находках сохраняются координаты и хеши без значений токенов.

### Ссылки в схемах MCP

`MC004` отмечает со средним уровнем `$ref` или начальную цель `$dynamicRef` за пределами захваченных ресурсов схемы инструмента. Проверка охватывает списки инструментов, JSON-RPC `result.tools` и импортированные снимки. Ссылки на фрагменты и встроенные ресурсы той же схемы считаются локальными. Значения примеров и расширений не участвуют в проверке.

Проверка использует часть ключевых слов [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core). Неизвестные или некорректные идентификаторы ресурсов, неподдерживаемые диалекты и URI длиннее 4096 байт могут оставить пробелы. Другие схемы остаются в охвате. Scout указывает координаты и хеш ссылки без её загрузки и проверки поведения клиента при запуске.

## Что можно подключить

### Свои и сторонние YARA-правила

`--yara` дополняет встроенные сигнатуры одним файлом с одним или несколькими
правилами, совместимыми с YARA-X. Например, сохраните доверенное правило
в `/etc/scout/organization.yar`:

```yara
rule organization_review_marker {
    strings:
        $marker = "SCOUT_REVIEW_REQUIRED"
    condition:
        $marker
}
```

```sh
scout scan --yara /etc/scout/organization.yar --fail-on medium ./my-plugin
```

Храните доверенный файл правил вне входа. Пример даёт `YR5` уровня Medium и задаёт тот же порог политики. Для выпуска и отката используйте [версионируемые наборы правил](usage.ru.md#версионируемые-наборы-правил).

### Поиск известных уязвимостей через OSV

OSV проверяет точные координаты захваченных зависимостей. Включите проверку отдельно с явным разрешением сети или доверенным кешем. [Настройка OSV и формат кеша](usage.ru.md#сетевые-сервисы-и-дополнительные-rules)

### LLM-проверка

Профиль `review` подключает настроенного провайдера и требует явного согласия на отправку исходных данных. Флаг `--quality-review` добавляет проверку качества. [Подключение и режимы семантической проверки](semantic-review.ru.md)

Новые статические анализаторы включаются в сборки Scout. [Обход внешних ссылок](../reference/external-sources.ru.md) расширяет набор входов для существующих проверок.

## Standard

```sh
scout scan --profile standard ./my-plugin
```

Профиль по умолчанию включает встроенные проверки, адаптированные шаблонные правила,
Python, YAML, TOML и YARA-X. Загрузки, OSV и LLM автоматически не включаются.
Недоступность обязательного движка вызывает ошибку до сканирования.
В именованном профиле нельзя отключить обязательную проверку.

## Custom

```bash
scout scan --profile custom --checks none --format markdown ./my-skill
scout scan --profile custom --checks python,yaml,toml,patterns ./my-skill
```

Первый пример выбирает только встроенные проверки; второй — необязательные проверки
без YARA. В CLI профиль custom начинается с полного набора, а `--checks` заменяет
этот список целиком. В Go задайте `Profile = scout.Custom`
и ненулевой `Checks`. См. [настройку API](../development/go-api.ru.md#создание-и-закрытие-scanner).

## Review

Профиль добавляет к standard выбранную оператором LLM. Настройте адрес, модель и учётные данные и разрешите отправку исходных данных. OSV и проверка качества включаются отдельно. [Включение семантической проверки](semantic-review.ru.md#включение)

В CLI также есть псевдонимы `basic` для custom со встроенными проверками, `extended` для standard и `semantic` для review. В конфигурации и Go используйте полные имена.

## Область проверки

`complete` означает завершение выбранных проверок. Консервативная политика
по умолчанию также требует ручной проверки при заявленных ограничениях анализа языков.
Явный `--scope selected` допускает эти ограничения, но не ошибки разбора,
незавершённую работу или исчерпанные лимиты. См. [поддержку языков](../reference/languages.ru.md).
