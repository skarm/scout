`scout profiles` перечисляет профили, `scout capabilities` показывает доступные
движки. `scout config validate` проверяет конфигурацию до чтения входа.

## Что встроено

Полная сборка с профилем `standard` выполняет следующие проверки без сети
и без установки дополнительных сканеров:

- **Инструкции агента:** попытки переопределить системные правила, скрыть действия
  от пользователя, раскрыть привилегированные промпты, передать секреты или закрепить
  инструкции в памяти для будущих сессий.
- **Конфигурации навыков, плагинов и MCP:** обход подтверждений и sandbox, широкие
  разрешения, команды lifecycle hooks, незакреплённые версии launcher-пакетов,
  открытый HTTP и чувствительные данные в декларациях.
- **Код и потоки данных:** выбранные операции запуска команд, `eval`, чтения
  секретов, передачи данных в сеть, небезопасной десериализации, построения SQL
  и отключения проверки TLS. Есть проверки Go, Shell, JavaScript/TypeScript,
  Python и SQL; покрытие различается по языкам.
- **Зависимости и состав пакета:** подмена источников пакетов, локальные замены
  Go modules, автоматический запуск при установке, непроверенные локальные
  компоненты и непрозрачные исполняемые вложения.
- **Скрытое содержимое:** HTML-инструкции, выбранные Unicode-контролы и confusables,
  NUL и несоответствия содержимого подсказкам имени файла. Поддерживаемые вложения
  распаковываются или декодируются в пределах лимитов и тоже проверяются.
- **Инструменты:** коллизии идентификаторов, подозрительные описания и параметры,
  сочетания доступа к чувствительным данным и сетевых возможностей.
- **Адаптированные правила SkillSpector:** дополнительные шаблонные и структурные
  проверки prompt injection, доступа к секретам, полномочий, инструментов
  и цепочки поставки.
- **Встроенные YARA-X-сигнатуры:** malware, webshells, cryptominers, hacktools,
  угрозы в навыках агентов и составные правила, адаптированные из Cisco skill-scanner.

JSON разбирается встроенными средствами; полная сборка также включает Tree-sitter
для Python и JS/TS, парсеры YAML/TOML и движок YARA-X. Сокращённая core-сборка
не содержит полного набора нативных движков и требует явного профиля `custom`.
Разбор синтаксиса сам по себе не является проверкой всех возможных действий программы.

Посмотреть идентификаторы, описания, методы и ограничения правил:

```sh
scout rules list
scout rules list --all
scout capabilities
```

`rules list` показывает базовый каталог; `--all` добавляет описания адаптированных,
Python- и YARA-проверок. Это каталог возможностей, а не список реально выполненных
проверок: выбранный план, применимость и результаты отражаются в отчёте.
Границы анализа описаны в [поддержке языков](../reference/languages.ru.md),
происхождение наборов — в [источниках адаптаций](../reference/port-manifest.ru.md).

## Что можно подключить

### Свои и сторонние YARA-правила

`--yara-rules` дополняет встроенные сигнатуры одним файлом с одним или несколькими
правилами, совместимыми с YARA-X. Например, сохраните доверенное правило
в `/etc/scout/organization.yar`:

```yara
rule organization_review_marker {
    strings:
        $marker = "SCOUT_REVIEW_REQUIRED"
    condition:
        $marker
}
```

```sh
scout scan --yara-rules /etc/scout/organization.yar --fail-on medium ./my-plugin
```

Пересборка Scout не нужна. Файл правил должен находиться вне проверяемого пакета.
Директивы `include` и модуль `console` запрещены; невалидные правила завершают
операцию ошибкой. Сигнатурное совпадение остаётся находкой для оценки в контексте.
В этом примере оно отображается как `YR5` с уровнем `medium`; `--fail-on medium`
задаёт соответствующий порог блокировки. Наличие находки и решение политики —
разные части отчёта.

### Поиск известных уязвимостей через OSV

```sh
scout scan --vuln --allow-vulnerability-network ./my-plugin
```

Проверка по точным координатам захваченных зависимостей включается отдельно.
Можно задать совместимый сервис через `--osv-endpoint` или работать без сети
с доверенным кешем через `--osv-cache`. Встроенной актуальной базы CVE нет.
Примеры и ограничения — в [руководстве CLI](usage.ru.md#сетевые-сервисы-и-дополнительные-rules).

### LLM-проверка

Профиль `review` добавляет настроенного LLM-провайдера к статическим проверкам.
Поддержаны Chat Completions, Anthropic Messages, `anthropic-proxy` и Bedrock;
дополнительная проверка качества включается через `--quality-review`.
Нужны явные настройки сервиса и `--allow-source-upload`.
Пример приведён [ниже](#review), детали — в [семантической проверке](semantic-review.ru.md).

Это поддерживаемые способы расширения без изменения исходников. CLI не загружает
произвольные сторонние движки анализа как плагины. Новые статические анализаторы
добавляются в код Scout. `--follow-external --allow-download` расширяет набор
проверяемых внешних исходников, используя существующие проверки;
см. [внешние источники](../reference/external-sources.ru.md).

## Standard

```sh
scout scan --profile standard ./my-plugin
```

Профиль по умолчанию включает встроенные проверки, адаптированные шаблонные правила,
Python, YAML, TOML и YARA-X. Загрузки, OSV и LLM автоматически не включаются.
Недоступность обязательного движка вызывает ошибку до сканирования.
В именованном профиле нельзя отключить обязательную проверку.

## Custom

```bash
scout scan --profile custom --checks none --format markdown ./my-skill
scout scan --profile custom --checks python,yaml,toml,patterns ./my-skill
```

Первый пример выбирает только встроенные проверки; второй — необязательные проверки
без YARA. В CLI профиль custom начинается с полного набора, а `--checks` заменяет
этот список целиком. В Go задайте `Profile = scout.Custom`
и ненулевой `Checks`. См. [настройку API](../development/go-api.ru.md#создание-и-закрытие-scanner).

## Review

```bash
scout scan --profile review --semantic --allow-source-upload \
  --llm-provider chat-completions \
  --llm-endpoint https://trusted.example/v1/chat/completions \
  --llm-model YOUR_MODEL --llm-api-key-env REVIEW_API_KEY ./my-plugin
```

Review добавляет к стандартным проверкам настроенного провайдера. Адрес сервиса,
модель, учётные данные и согласие на передачу исходников задаёт оператор.
Проверка качества и OSV включаются отдельно. См. [семантическую проверку](semantic-review.ru.md).

CLI также принимает альтернативные имена: `basic` — custom со встроенными проверками,
`extended` — standard, `semantic` — review. В конфигурации и Go используются полные имена.

## Область проверки

`complete` означает завершение выбранных проверок. Консервативная политика
по умолчанию также требует ручной проверки при заявленных ограничениях анализа языков.
Явный `--scope selected` допускает эти ограничения, но не ошибки разбора,
незавершённую работу или исчерпанные лимиты. См. [поддержку языков](../reference/languages.ru.md).
