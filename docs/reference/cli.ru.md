## Синтаксис и справка

```sh
scout -h
scout scan -h
scout scan -f json ./my-plugin
scout scan --format json -- "$target"
scout scan --stdin SKILL.md -f json < ./SKILL.md
```

Полный справочник выводится по флагу `--help` (`-h`) в корне или по команде
`scout help`. Команда `scout scan -h` показывает флаги сканирования и их значения
по умолчанию. Команды с парсером флагов принимают оба варианта перед входами.

Указывайте флаги перед позиционными входами. `--` завершает разбор параметров;
для обычного пути вроде `./my-plugin` он необязателен. Сохраняйте разделитель перед
путём из переменной или именем, начинающимся с `-`. После `--` каждый аргумент
считается входом, даже если похож на флаг.

Булевый флаг без значения включает опцию. Для отключения используйте
`--flag=false`, а не `--flag false`. Лимиты байтов задаются целыми числами без
суффиксов `MiB`. Длительности требуют единиц, например `500ms`, `30s`, `2m`
или `168h`. Указанные ниже значения по умолчанию действуют без конфигурации; явные флаги
переопределяют поля из `--config`. Разрешения всегда задаются текущим запуском.

## Команды

```text
scout scan [flags] <target> [target...]
scout scan [flags] --stdin NAME
scout compare [flags] <before> <after>
scout discover [flags] [--scan -- <scan flags>]
scout config validate [flags]
scout mcp [flags]
scout mcp snapshot --source-id ID [--output FILE] <capture.json>
scout doctor [flags]
scout baseline create|approve|renew [flags]
scout policy shadow --report FILE --current FILE --trial FILE [flags]
scout rules list [--all]
scout rules pack create|inspect [flags]
scout profiles
scout capabilities
scout knowledge [--mode MODE]
scout integrations list
scout integrations export --bundle NAME --output FILE
scout registry fetch [flags]
scout registry compare [--output FILE] <previous> <current>
scout attestation verify --public-key KEY --envelope FILE --artifact FILE --subject NAME
scout version
```

Действующие aliases: `batch` для `scan`, `selftest` для `doctor`, `rules` для
`rules list`, `integrations` для `integrations list`, корневой `--version` для
`version`. Сканирование принимает от 1 до 32 локальных путей или явных HTTP(S) URL.
Через stdin можно передать один именованный вход без позиционных целей.

## Обнаружение окружения

`scout discover` выводит инвентарь Codex, Claude Code, Cursor, GitHub Copilot CLI, OpenCode, Gemini CLI, OpenClaw, Grok CLI, DeepSeek Harness, ZCode и Qwen Code. Флаг `--scan` передаёт найденные
корни существующему Scanner. См. [расположения, формат и ограничения](../user/discovery.ru.md).

- `--agent all|codex|claude-code|cursor|copilot-cli|opencode|gemini-cli|openclaw|grok-cli|deepseek-harness|zcode|qwen-code` (`-a`): агент; по умолчанию `all`.
- `--home DIR`: домашний каталог; по умолчанию каталог текущего пользователя.
- `--codex-home DIR`, `--claude-home DIR`, `--cursor-home DIR`, `--copilot-home DIR`, `--opencode-home DIR`: явные каталоги конфигурации агентов.
  Без `--home` учитываются `CODEX_HOME` и `CLAUDE_CONFIG_DIR` процесса.
- `--gemini-home DIR`: каталог, содержащий `.gemini` и `.agents`. Без `--home` учитывается `GEMINI_CLI_HOME`.
- `--openclaw-home DIR`: каталог состояния OpenClaw. Без `--home` учитывается `OPENCLAW_STATE_DIR`.
- `--grok-home DIR` указывает непосредственно на каталог конфигурации Grok. Без `--home` учитывается `GROK_HOME`.
- `--deepseek-home DIR` указывает непосредственно на каталог DeepSeek Harness. Без `--home` учитывается `DSH_HOME`.
- `--zcode-home DIR` указывает непосредственно на каталог ZCode, по умолчанию `~/.zcode`.
- `--qwen-home DIR` указывает непосредственно на каталог Qwen Code. По умолчанию используется `QWEN_HOME` или `~/.qwen`. При явном `--home` переменная окружения игнорируется.
- `--project DIR`: повторяемый выбранный проект; по умолчанию текущий каталог.
- `--no-project`: исключить проекты; по умолчанию `false`.
- `--system[=BOOL]`: известные системные расположения; по умолчанию `true`.
- `--max-entries N`: суммарные пробы/записи каталогов; по умолчанию 10000, 1..100000.
- `--max-depth N`: глубина обхода навыков/плагинов; по умолчанию 12, 1..32.
- `--max-bytes N`: суммарные байты конфигураций/манифестов; по умолчанию 8388608,
  1..67108864. Один файл ограничен 256 КиБ.
- `--timeout DURATION` (`-t`): срок обнаружения; по умолчанию `10s`, больше 0 и не более `2m`.
- `--format text|json` (`-f`): формат инвентаря; по умолчанию `text`.
- `--output FILE` (`-o`): инвентарь вне проверяемых входов; по умолчанию stdout.
- `--scan`: проверка найденных корней; по умолчанию `false`. Обычные флаги scan
  задаются после `--`. Флаги инвентаря `--format`/`--output` в этом режиме отвергаются.
- `--snapshot FILE` (`-s`) сохраняет найденное окружение. Выберите одного агента
  и передайте флаги сканирования после `--`.
- `--kind skill|plugin|mcp-server|command|hook|agent|rule|tool|lsp-server|workflow|channel` (`-k`): повторяемый выбор типа компонентов;
  без фильтра сохраняются исходные сгруппированные корни.
- `--include-path PATH`: повторяемое пересечение с найденными корнями; пути вне
  инвентаря не добавляются.
- `--exclude-path PATH`: повторяемое исключение целых пересекающихся корней.
  Для выбора отдельных компонентов используйте `--kind` перед исключением путей.

Инвентарь имеет схему `scout.environment/v1`; код 0 означает полный результат
в документированной области, код 2 — ошибку или неполноту. Это не решение политики.
Режим `--scan` требует полного обнаружения и 1..32 корней; возвращает обычный
отчёт сканирования и его код. Состояния деклараций не устанавливают активность компонентов.

## Флаги scan

### Вход и конфигурация

- `--environment` (`--env`): явно сопоставить выбранные локальные корни как окружение одного
  агента/проекта; по умолчанию `false`. Обычные входы остаются независимыми.
  Требуются существующие непересекающиеся корни; внешний обход не поддерживается.
  См. [анализ окружения](../user/environment-analysis.ru.md).

- `--config FILE` (`-c`): явная JSON-конфигурация оператора; по умолчанию не задана.
  Допускается только один раз. Конфигурация не ищется внутри проверяемых целей.
- `--profile standard|review|custom` (`-p`): профиль проверки; по умолчанию `standard`.
  `standard` выбирает все статические проверки; `review` также требует настроенного
  reviewer; `custom` допускает явный выбор проверок. Aliases CLI: `extended` =
  `standard`, `semantic` = `review`, `basic` = `custom` со всеми отключёнными
  необязательными статическими проверками.
- `--harness auto|claude-code|codex|cursor|copilot-cli|opencode|gemini-cli|openclaw|grok-cli|deepseek-harness|zcode|qwen-code|agent-skills`: интерпретация деклараций агентов
  и плагинов; по умолчанию `auto`.
- `--stdin NAME` (`-i`) читает один вход из stdin. Укажите относительное имя файла,
  например `SKILL.md`, для определения формата и координат исходников.
  Позиционные входы в этом режиме опускаются.
- `--exclude GLOB` исключает файлы при прямом сканировании одного локального
  каталога навыка. Флаг можно повторять, например
  `scout scan --exclude 'tests/*' --exclude 'fixtures/*.json' ./my-skill`.
  Шаблон сопоставляется со всем относительным POSIX-путём с учётом регистра.
  Символ `*` может охватывать несколько уровней каталогов. Кавычки передают
  шаблон в Scout без подстановки оболочкой. Поддерживается до 32 шаблонов,
  каждый размером до 256 байт в UTF-8.

Каталог должен содержать ровно один манифест в корне. Шаблоны, совпадающие
с `SKILL.md` или `skill.md`, отклоняются. Защита также применяется к
фактическому манифесту с другим написанием регистра. JSON хранит все шаблоны
в поле `artifact.exclude_globs`, даже если совпадений нет. Исключённые
файлы видны в отчёте со статусом `skipped` и причиной `operator_excluded`
и учитываются в покрытии. Если исключён хотя бы один файл, покрытие считается
неполным и команда возвращает код 2.

Храните конфигурацию, baseline, дополнительные правила и кеши вне всех проверяемых
входов. См. [конфигурацию](../user/usage.ru.md#конфигурация) и
[профили](../user/inspection-profiles.ru.md).
Для типового сценария скопируйте [готовый конфиг](../../examples/configs/README.ru.md).

### Отчёты

- `--format text|json|sarif|markdown` (`-f`): формат основного отчёта; по умолчанию `text`.
  `terminal` — alias для `text`.
- `--output FILE` (`-o`): назначение основного отчёта; по умолчанию stdout. Существующий
  обычный файл заменяется атомарно; каталоги и символические ссылки отвергаются.
- `--report FORMAT=PATH` (`-r`): дополнительный отчёт; повторяемый, по умолчанию отсутствует.
  Форматы совпадают с `--format`. Назначения должны различаться и находиться вне
  проверяемых входов и доверенных файлов оператора. Основной отчёт тоже формируется.

Диагностика идёт в stderr. Создавайте каталоги назначения перед запуском.
Для файловых отчётов границы входов должны разрешаться: входная символическая
ссылка с отсутствующей целью отвергается. Для диагностики такого входа используйте stdout.
См. [сохранение отчётов](../user/usage.ru.md#сохранение-отчётов).

### Политика

- `--fail-on info|low|medium|high|critical` (`--fo`): минимальная серьёзность неподавленной
  находки, блокирующей установку; по умолчанию `high`. Другие причины политики могут
  требовать ручной проверки; неполный запуск по-прежнему возвращает код 2.
- `--scope conservative|selected`: политика покрытия языков; по умолчанию
  `conservative`. `selected` допускает заявленные ограничения анализа языка,
  но не ошибки разбора, незавершённые проверки или исчерпанные лимиты.
- `--baseline FILE` (`-b`): доверенный JSON baseline оператора; по умолчанию не задан.
- `--allow-baseline-globs`: разрешить исключения по маске в baseline;
  по умолчанию `false`.

См. [baseline](../user/usage.ru.md#baseline) и
[политику покрытия](../user/inspection-profiles.ru.md#область-проверки).

### Необязательные статические проверки

- `--checks LIST` (`--chk`): полный список необязательных статических проверок через запятую.
  По умолчанию без конфигурации: `python,yaml,toml,yara,patterns`; для alias профиля
  `basic` — `none`. Явный список заменяет набор из конфигурации целиком.
  Имена: `python` — проверки Python AST, `yaml` и `toml` — структурный разбор,
  `yara` — нативные YARA-X-сигнатуры, `patterns` — адаптированные проверки SkillSpector.
  `none` отключает все необязательные статические проверки. Встроенные обязательные
  проверки всегда остаются включёнными. Флаг задаётся один раз; пустые, неизвестные,
  повторяющиеся имена и сочетание `none` с другими именами отвергаются.
- `--yara FILE` (`-y`): дополнительные доверенные YARA-правила; по умолчанию не заданы.
  Требуют включённого YARA. Include и вывод в консоль запрещены.

Сокращённый список и `none` требуют `--profile custom`; `standard` и `review`
требуют полный набор. Для одних встроенных проверок используйте
`--profile custom --checks none`.
См. [проверки и расширения](../user/inspection-profiles.ru.md).

### Параллелизм и лимиты

- `--rulepack FILE`: явно выбранный доверенный пакет дополнительных YARA-правил
  `scout.rulepack/v1`; по умолчанию не задан. Требует включённого YARA и несовместим
  с `--yara`. Файл должен находиться вне всех проверяемых входов.
- `--rulepack-sha256 DIGEST`: необязательный SHA-256 всех байтов пакета,
  64 шестнадцатеричных символа в нижнем регистре. Требует `--rulepack`; хеш охватывает
  версию и форматирование JSON. Несовпадение хеша или ABI прерывает инициализацию.
  Автоматической загрузки и подмены пакета нет.
- `--workers N` (`-w`): число параллельных обработчиков анализаторов, общее для входов операции; по умолчанию `4`,
  диапазон 1..32.
- `--target-workers N` (`--tw`): одновременно проверяемые входы; по умолчанию `1`,
  диапазон 1..32.
- `--timeout DURATION` (`-t`): срок всей операции сканирования или сравнения; по умолчанию
  `2m`, положительный и не больше `10m`.
- `--parser-timeout DURATION`: срок одного разбора парсером; по умолчанию `3s`,
  положительный и не больше `10s`.
- `--max-files N`: захваченные файлы на один вход; по умолчанию `4096`, положительное
  число не больше `--max-entries`.
- `--max-entries N`: элементы инвентаризации на один вход, включая отвергнутые;
  по умолчанию `8192`, диапазон 1..100000.
- `--max-file-bytes N`: байты одного захваченного файла; по умолчанию `1048576`
  (1 МиБ), диапазон 1..33554432.
- `--max-target-bytes N`: захваченные байты на один вход; по умолчанию `33554432`
  (32 МиБ), не меньше `--max-file-bytes` и не больше `268435456`.
- `--max-archive-bytes N`: байты исходного архива на один вход; по умолчанию
  `33554432`, диапазон 1..134217728.
- `--max-run-bytes N`: суммарные захваченные байты всего запуска; по умолчанию
  `33554432`, диапазон 1..268435456.
- `--max-operations N`: бюджет анализа, общий для входов и заданий; по умолчанию
  `16777216`, диапазон 1..1099511627776.
- `--max-matches-per-rule N`: потолок кандидатов совпадений на анализатор по файлам
  одного входа; по умолчанию `1024`, диапазон 1..100000.
- `--max-findings N`: сохраняемые находки всего запуска; по умолчанию `1024`,
  диапазон 1..100000. Пропуски из-за лимита делают запуск неполным.
- `--extract-depth N`: глубина рекурсивного извлечения; по умолчанию `4`,
  диапазон 1..16.
- `--extract-objects N`: производные объекты на один вход; по умолчанию `256`,
  диапазон 1..4096.
- `--extract-entries N`: посещённые элементы извлечения на один вход; по умолчанию
  `8192`, диапазон 1..100000.
- `--extract-object-bytes N`: байты одного производного объекта; по умолчанию
  `1048576`, диапазон 1..33554432.
- `--extract-bytes N`: извлечённые байты на один вход; по умолчанию `16777216`
  (16 МиБ), не меньше `--extract-object-bytes` и не больше `134217728`.

Лимиты одного входа также ограничены общими бюджетами запуска, поделёнными между
входами. В конфигурации дополнительно доступны `limits.max_extracted_bytes`
(по умолчанию 16 МиБ), `limits.max_capture_files` (4096),
`limits.max_capture_entries` (8192) и `limits.max_service_requests` (64);
отдельных CLI-флагов для них сейчас нет. Повышение лимита одного входа не повышает
соответствующий общий бюджет.

### Загрузки

- `--allow-download`: разрешить явную загрузку удалённых входов; по умолчанию `false`.
- `--download-timeout DURATION`: срок получения одного удалённого входа; по умолчанию `30s`,
  положительный и не больше `2m`. Используйте с `--allow-download`.
- `--download-allow-loopback`: разрешить явные числовые loopback-адреса загрузок
  и их обычные HTTP URL; по умолчанию `false`. Требует `--allow-download`.
- `--git`: обработать неоднозначный HTTPS URL как адрес клонирования Git. Требует `--allow-download`.
- `--revision SHA`: необязательный полный SHA коммита из 40 символов. Без него
  Git-сканирование захватывает удалённый `HEAD`. Требует `--allow-download`.
- `--git-auth-origin ORIGIN`, `--git-auth-user USER`, `--git-token-env NAME`:
  укажите все три флага для аутентификации Git по HTTPS. Scout читает токен из
  указанной переменной окружения и отправляет его только на заданный origin.
  Требует `--allow-download`.
- `--download-sha256 HEX`: ожидаемый SHA-256 всех загруженных байтов, 64
  шестнадцатеричных символа. Требует `--allow-download`. Применяется к прямым
  загрузкам и архивам GitHub. Для Git Smart HTTP используйте полный SHA коммита.

Флаги revision/checksum переопределяют соответствующие `remote_pins` конфигурации
для каждого удалённого входа текущего запуска.
См. [внешние источники](external-sources.ru.md).

### Внешние ссылки

- `--follow-external`: захватывать поддержанные буквальные ссылки на внешние
  исходники; по умолчанию `false`. Требует `--allow-download`.
- `--external-origin ORIGIN`: точный разрешённый origin; повторяемый. Задание флага
  заменяет значения по умолчанию: `https://raw.githubusercontent.com` и `https://github.com`.
- `--external-depth N`: максимальное число переходов по ссылкам; по умолчанию `2`,
  диапазон 1..8.
- `--external-max-requests N`: потолок запросов обхода на весь запуск; по умолчанию
  `16`, диапазон 1..64, также ограничен общим бюджетом сервисов.
- `--external-max-bytes N`: суммарные байты ответов обхода; по умолчанию `4194304`
  (4 МиБ), диапазон 1..33554432.

Все флаги `--external-*` требуют `--follow-external`. Разрешённые origins должны
использовать HTTPS, кроме явно разрешённых числовых loopback-адресов.

### Уязвимости

- `--osv`: включить поиск уязвимостей по точным координатам; по умолчанию `false`.
  При отсутствии ответа сети и кеша Scout ищет совпадения во встроенной подборке.
- `--allow-osv-network`: разрешить запросы координат пакетов отдельно
  от загрузок и передачи исходников; по умолчанию `false`.
- `--osv-cache FILE`: доверенный кеш точных запросов; по умолчанию не задан.
  Путь к кешу также включает сервис. Версия 1 содержит обычные ID уязвимостей;
  версия 2 также включает `MAL001` для явной классификации вредоносных пакетов.
  Свежие ответы версии 2 имеют приоритет перед обычными сетевыми запросами.
  Флаг `--osv=false`
  не переопределяет непустой путь к кешу.
- `--osv-snapshot-dir DIR`: каталог локальных выгрузок OSV `Go/all.zip`,
  `npm/all.zip` или `PyPI/all.zip`. Включает офлайн-поиск. Несовместим с
  `--allow-osv-network`. В файле конфигурации используется `vulnerabilities.snapshot_dir`.
- `--osv-cache-max-age DURATION`: максимальный возраст кеша; по умолчанию `168h`
  (7 дней), диапазон `1m`..`8760h`.
- `--osv-endpoint URL`: адрес запросов; по умолчанию
  `https://api.osv.dev/v1/querybatch`.
- `--osv-allow-loopback`: разрешить явный числовой loopback-адрес сервиса;
  по умолчанию `false`.
- `--osv-max-requests N`: потолок запросов с учётом ошибок, пагинации и карточек advisories. По умолчанию
  `128`, диапазон 1..256. Общий бюджет сервисов может его уменьшить.

Используйте настройки `--osv-*` с включённым сервисом. Встроенные совпадения
оставляют покрытие неполным и не входят в экспорт кеша точных запросов.
См. [использование OSV](../user/usage.ru.md#сетевые-сервисы-и-дополнительные-rules).

### LLM-проверка

- `--review` (`--llm`): включить reviewer, настроенный флагами; по умолчанию `false`.
  Объект `review` в конфигурации тоже включает сервис. `--review=false`
  отключает такой сервис; для отключения также выберите профиль, отличный от `review`.
- `--allow-source-upload`: разрешить передачу захваченных исходников;
  по умолчанию `false`. Требуется любому включённому reviewer, включая локальный.
- `--quality-review`: включить дополнительную оценку качества и политики;
  по умолчанию `false`.
- `--llm-provider chat-completions|anthropic|anthropic-proxy|bedrock`: транспорт
  провайдера; по умолчанию `chat-completions`.
- `--llm-endpoint URL`: явный доверенный адрес reviewer; по умолчанию не задан.
- `--llm-model NAME`: явная модель; по умолчанию не задана.
- `--llm-api-key-env NAME`: переменная окружения с API-ключом; по умолчанию не задана.
  Автопоиска учётных данных нет. Используется для провайдеров кроме Bedrock.
- `--llm-aws-region REGION`: регион Bedrock; по умолчанию не задан.
- `--llm-aws-access-key-env NAME`: переменная с access key Bedrock;
  по умолчанию не задана.
- `--llm-aws-secret-key-env NAME`: переменная с secret key Bedrock;
  по умолчанию не задана.
- `--llm-aws-session-token-env NAME`: необязательная переменная с session token
  Bedrock; по умолчанию не задана.
- `--llm-allow-loopback`: разрешить явный числовой loopback-адрес reviewer;
  по умолчанию `false`.
- `--llm-max-output-tokens N`: запрошенный потолок токенов ответа;
  по умолчанию `2048`, диапазон 128..8192.
- `--llm-max-response-bytes N`: потолок байтов HTTP-ответа провайдера;
  по умолчанию `65536` (64 КиБ). Он не повышает отдельный бюджет декодированного
  ответа reviewer.
- `--llm-max-requests N`: запросы семантической проверки на один вход, общие для проходов;
  по умолчанию `64`, диапазон 1..256. Общий бюджет сервисов запуска может уменьшить этот предел.
- `--llm-max-input-bytes N`: байты сериализованных пользовательских запросов на весь запуск,
  общие для входов и проходов; по умолчанию `2097152` (2 МиБ), диапазон 32768..8388608.
- `--llm-timeout DURATION`: срок одного запроса провайдеру; по умолчанию `30s`,
  положительный и не больше `2m`, также ограничен сроком всей операции.

Настройки провайдера и качества требуют включённого reviewer. `--profile review`
по-прежнему требует `--review`, если reviewer задаётся только флагами.
См. [семантическую проверку](../user/semantic-review.ru.md) для условий согласия
и требований провайдеров.

## Сравнение

`compare` требует ровно два локальных пути. Поддерживает флаги конфигурации,
отчётов, политики, проверок, параллелизма, лимитов, OSV и reviewer из `scan`.

- `--max-changes N`: максимум сохраняемых изменений сравнения; по умолчанию
  `4096`, диапазон 1..20000. Усечение делает сравнение неполным.
- `--pr-head OWNER/REPO@SHA` включает сравнение статических возможностей.
  Для GitLab укажите `PROJECT_URL@SHA`. SHA коммита должен быть полным, в нижнем
  регистре. Markdown становится форматом по умолчанию и выводит компактную
  сводку со ссылками на строки коммита.
- `--pr-provider github|gitlab` выбирает формат ссылок. По умолчанию `github`.
  При явном указании требует `--pr-head`.
- `--pr-path DIR` добавляет к ссылкам относительный POSIX-путь к каталогу
  в репозитории. Для одиночного файла укажите его родительский каталог.
  Требует `--pr-head`.
- `--approved-sha256 DIGEST` передаёт одобренный SHA-256 снимка пакета
  кандидата, 64 шестнадцатеричных знака в нижнем регистре. Совпадение закрывает
  требование ревью из-за изменения содержимого. При несовпадении требуется
  проверка. При неполной проверке код завершения остаётся `2`.

Тайм-аут и общие бюджеты охватывают оба сканирования и сравнение.
См. [сравнение обновлений](../user/update-review.ru.md).

## Валидация конфигурации

`config validate` использует флаги конфигурации, политики, статических проверок,
параллелизма, лимитов и сервисов из `scan`, чтобы создать и проверить Scanner
без входов. `--config FILE` (`-c`) необязателен. При его отсутствии проверяются
настройки по умолчанию.
Результат — подготовленный план проверки, всегда в JSON в stdout.

## Сервер MCP

`mcp` использует флаги конфигурации, политики, статических проверок, параллелизма,
лимитов и сервисов из `scan`. Входы разрешаются через `--target` или передаются
загрузкой инструмента. Отчёты возвращаются в ответах инструментов.

- `--transport stdio|http`: транспорт; по умолчанию `stdio`.
- `--listen ADDRESS`: числовой loopback-адрес HTTP-сервера; по умолчанию
  `127.0.0.1:8837`.
- `--token-env NAME`: переменная окружения с HTTP bearer token;
  по умолчанию не задана. Обязательна для HTTP; токен содержит 32..512 байтов
  без пробельных символов.
- `--tool-timeout DURATION`: срок каждого допущенного вызова инструмента;
  по умолчанию `1m`, положительный и не больше `10m`. `--timeout` также
  ограничивает операцию Scanner.
- `--concurrency N`: параллелизм вызовов инструмента между сессиями;
  по умолчанию `2`, диапазон 1..8.
- `--target NAME=LOCAL_PATH`: разрешённый именованный локальный вход; повторяемый,
  по умолчанию отсутствует, максимум 64. Клиент инструмента выбирает имя вместо
  произвольного пути.
- `--origin ORIGIN`: явно разрешённый браузерный HTTP Origin; повторяемый,
  по умолчанию отсутствует. Пустой список запрещает браузерные origins. Только для HTTP.

`--token-env` тоже предназначен только для HTTP. Без именованных целей
используйте загрузку содержимого.
См. [настройку MCP](../user/integrations.ru.md#mcp-server).

`mcp snapshot` импортирует локальные данные MCP. Флаг `--source-id ID` задаёт
стабильный идентификатор источника, а `--output FILE` (`-o`) сохраняет снимок в файл.

## Doctor

`doctor` (alias `selftest`) проверяет подключённые нативные движки.

- `--format text|json` (`-f`): формат; по умолчанию `terminal`, alias для `text`.
- `--timeout DURATION` (`-t`): кооперативный срок всей самопроверки; по умолчанию `90s`,
  положительный и не больше `2m`.

## Baseline

Команды `baseline create`, `baseline approve` и `baseline renew` принимают:

- `--from FILE`: обязательный источник. `create` читает валидированный JSON-отчёт
  с одним входом; `approve` и `renew` — JSON-документ baseline.
- `--output FILE` (`-o`): назначение вне источника; обязательно, кроме режима `--dry-run`.
- `--reason TEXT`: обоснование оператора; обязательно для непустых create/approve.
  Renew сохраняет прежние обоснования, если параметр не указан.
- `--expires RFC3339`: обязательный будущий срок, например `2099-01-01T00:00:00Z`.
- `--fingerprint SHA256`: повторяемый выбор точных записей для approve/renew;
  без параметра выбираются все. Неизвестные, повторные и некорректные значения
  отклоняются до записи.
- `--dry-run` (`-d`): JSON-предпросмотр изменений `scout.baseline-preview/v1` в stdout
  без записи baseline. `--output` необязателен; указанный путь проверяется.

`create` пишет неодобренные записи. `approve` одобряет выбранные записи. `renew`
только продлевает одобренные записи; выбор неодобренной записи или срока не позднее
прежнего отклоняется. Без селекторов неодобренные записи сохраняются. Остальные
записи сохраняют обоснования и сроки. См. [работу с baseline](../user/usage.ru.md#baseline).

## Теневой прогон политики

```sh
scout policy shadow --report scan.json --current current.json --trial trial.json --format json
```

- `--report FILE` выбирает сохранённый JSON `scout.report/v1` от `scan` или
  `compare` размером до 64 МиБ.
- `--current FILE` и `--trial FILE` выбирают две конфигурации оператора
  `scout.config/v1`. Команда применяет только раздел `policy`, включая явно
  заданные baseline. Каждая политика использует значения CLI по умолчанию
  для отсутствующих полей. Если при сканировании параметры политики были
  переопределены флагами, внесите эти значения в текущую конфигурацию.
- `--at RFC3339` задаёт общий момент оценки двух политик и проверки сроков
  исключений. По умолчанию используется время запуска команды.
- `--format text|json` (`-f`) выбирает формат вывода в stdout. По умолчанию
  используется текст.

Пример пробной политики с блокировкой для критических находок и ручной
проверкой остальных:

```json
{"schema":"scout.config/v1","policy":{"fail_at":"critical","review_below_threshold":true}}
```

Обе политики применяются к одним и тем же сохранённым наблюдениям без нового
сканирования. Исключения берутся из переданных конфигураций. В результате
видны оба решения, их причины и изменения статуса отдельных находок
(`block`, `review`, `below_threshold`, `suppressed`), а также изменения
для сигналов манифеста. Для сохранённого сравнения статусы находок относятся
к проверяемой версии. JSON использует схему `scout.policy-shadow/v1`
и включает хеши обеих политик.

Код команды 0 означает, что результат сформирован, а 2 указывает на ошибку.
Прогнозируемые коды допуска выводятся отдельно для каждой политики.
Неполный исходный прогон даёт прогнозируемый код 2.

## Registry

`registry fetch` не принимает позиционных входов и поддерживает:

- `--endpoint URL`: адрес servers реестра; по умолчанию

  по умолчанию `false`.
- `--max-pages N`: потолок страниц; по умолчанию `32`, диапазон 1..128.

  диапазон 1..33554432.
- `--output FILE` (`-o`): назначение JSON-снимка; по умолчанию stdout.

`registry compare` принимает два пути снимков: предыдущий и текущий.

См. [снимки реестра](external-sources.ru.md#mcp-registry).

## Проверка аттестации

`attestation verify` требует все четыре флага, по умолчанию не заданные:

- `--public-key FILE`: явный доверенный PKIX public key PEM вне проверяемых входов.
- `--envelope FILE`: DSSE envelope или OMS bundle.
- `--artifact FILE`: обычный файл артефакта, чьи точные байты должны соответствовать подписи.
- `--subject NAME`: точное имя подписанного subject.

См. [проверку подписей](external-sources.ru.md#проверка-dssein-toto).

## Коды завершения

Для сканирования и сравнения: `0` — полный запуск и allow; `1` — полный запуск
с review или block; `2` — неполнота, отмена, неверный запрос или ошибка записи.
Доступные отчёты полезны и при ненулевом коде завершения.

Для проверки аттестации: `0` — соответствие; `1` — несовпадение подписи или subject;
`2` — неверные входы или операционная ошибка. Doctor возвращает `2` при провале
нативной самопроверки. Другие операторские команды используют `0` для успеха
и `2` для ошибки.

### Пакеты правил

`scout rules pack create --id ID --version VERSION --yara FILE [--output FILE]`
упаковывает доверенный UTF-8 исходник дополнительных правил в воспроизводимый JSON.
По умолчанию пакет выводится в stdout. Для записи в файл используйте
`--output FILE` (`-o`). Запись не может затереть исходник.
Команда требует `--id`, `--version` (`-v`) и `--yara` (`-y`)
и отклоняет позиционные аргументы.
Создание проверяет метаданные и лимиты, но не компилирует YARA.

`scout rules pack inspect [--sha256 DIGEST] FILE` проверяет точные поля схемы,
совместимость `scout.yara-source/v1`, хеш исходника и необязательный независимо
полученный хеш всего пакета. Выводит только JSON идентичности без текста правил.
Установки, компиляции и сетевых обращений нет. При инициализации сканера выбранные
правила компилируются; невалидный YARA, includes и console отклоняются.

Обе команды работают с явно выбранными локальными файлами. Лимит пакета — 256 КиБ
вместе с экранированием JSON и метаданными; исходник также ограничен 256 КиБ.
Хеш подтверждает тождество байтов, но не подлинность издателя. Конфигурация и откат
описаны в [руководстве](../user/usage.ru.md#версионируемые-наборы-правил).

## Снимки окружения

```text
scout snapshot create --snapshot FILE --root ID=PATH [local scan flags]
scout snapshot compare --snapshot FILE --root ID=PATH [compare flags]
scout snapshot compare --snapshot FILE --empty [compare flags]
scout snapshot compare --snapshot FILE --candidate FILE [compare flags]
scout snapshot compare --snapshot FILE --save-candidate NEW_FILE [compare flags]
scout snapshot compare --snapshot FILE [--source-diff] [compare flags]
scout snapshot inspect --snapshot FILE [--format text|json]
scout discover --agent AGENT --snapshot FILE [discovery flags] -- [local scan flags]
```

`--snapshot FILE` (`-s`) задаёт новый снимок для create или сохранённый для compare.
Повторяйте `--root` для полного текущего набора. `--empty` явно выбирает пустой набор.
`snapshot inspect` принимает `--format text|json` (`-f`).
`snapshot compare` принимает `--format text|json|markdown|sarif` и `--report FORMAT=PATH`.
См. [снимки окружения](../user/environment-snapshots.ru.md).

Без `--root`, `--empty` и `--candidate` сравнение повторяет сохранённый discovery или проверяет сохранённые пути.
`--candidate` читает второй снимок и несовместим с `--root`, `--empty` и `--save-candidate`.
`--save-candidate` сохраняет текущие байты из сравнения и отчёт их проверки в новый файл.
`--source-diff` явно включает ограниченные фрагменты исходников в отчёт.
