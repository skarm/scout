## Синтаксис и справка

```sh
scout -h
scout scan -h
scout scan --format json ./my-plugin
scout scan --format json -- "$target"
scout scan --input - --name SKILL.md --format json < ./SKILL.md
```

`scout -h`, `scout --help` и `scout help` печатают полный справочник команд и флагов.
`scout scan -h` и `scout scan --help` показывают параметры сканирования и значения
по умолчанию. Команды с парсером флагов также принимают `-h` и `--help` перед входами.

Указывайте флаги перед позиционными входами. `--` завершает разбор параметров;
для обычного пути вроде `./my-plugin` он необязателен. Сохраняйте разделитель перед
путём из переменной или именем, начинающимся с `-`. После `--` каждый аргумент
считается входом, даже если похож на флаг.

Булевый флаг без значения включает опцию. Для отключения используйте
`--flag=false`, а не `--flag false`. Лимиты байтов задаются целыми числами без
суффиксов `MiB`. Длительности требуют единиц, например `500ms`, `30s`, `2m`
или `168h`. Указанные ниже defaults действуют без конфигурации; явные флаги
переопределяют поля из `--config`. Разрешения всегда задаются текущим запуском.

## Команды

```text
scout scan [flags] <target> [target...]
scout scan [flags] --input - --name <relative-name>
scout compare [flags] <before> <after>
scout discover [flags] [--scan -- <scan flags>]
scout config validate [flags]
scout mcp [flags]
scout doctor [flags]
scout baseline create|approve [flags]
scout rules list [--all]
scout profiles
scout capabilities
scout knowledge [--mode MODE]
scout integrations list
scout integrations export --bundle NAME --output FILE
scout registry fetch [flags]
scout registry compare [--output FILE] <previous> <current>
scout attestation verify --public-key KEY --envelope FILE --artifact FILE --subject NAME
scout version
```

Действующие aliases: `batch` для `scan`, `selftest` для `doctor`, `rules` для
`rules list`, `integrations` для `integrations list`, корневой `--version` для
`version`. Сканирование принимает от 1 до 32 локальных путей или явных HTTP(S) URL.
Через stdin можно передать один именованный вход без позиционных целей.

## Обнаружение окружения

`scout discover` выводит инвентарь Codex и Claude Code; `--scan` передаёт найденные
корни существующему Scanner. См. [расположения, формат и ограничения](../user/discovery.ru.md).

- `--agent all|codex|claude-code`: агент; по умолчанию `all`.
- `--home DIR`: домашний каталог; по умолчанию каталог текущего пользователя.
- `--codex-home DIR`, `--claude-home DIR`: явные каталоги конфигурации агентов.
  Без `--home` учитываются `CODEX_HOME` и `CLAUDE_CONFIG_DIR` процесса.
- `--project DIR`: повторяемый выбранный проект; по умолчанию текущий каталог.
- `--no-project`: исключить проекты; по умолчанию `false`.
- `--system[=BOOL]`: известные системные расположения; по умолчанию `true`.
- `--max-entries N`: суммарные пробы/записи каталогов; по умолчанию 10000, 1..100000.
- `--max-depth N`: глубина обхода навыков/плагинов; по умолчанию 12, 1..32.
- `--max-bytes N`: суммарные байты конфигураций/манифестов; по умолчанию 8388608,
  1..67108864. Один файл ограничен 256 КиБ.
- `--timeout DURATION`: срок обнаружения; по умолчанию `10s`, больше 0 и не более `2m`.
- `--format text|json`: формат инвентаря; по умолчанию `text`.
- `--output FILE`: инвентарь вне проверяемых входов; по умолчанию stdout.
- `--scan`: проверка найденных корней; по умолчанию `false`. Обычные флаги scan
  задаются после `--`. Флаги инвентаря `--format`/`--output` в этом режиме отвергаются.

Инвентарь имеет схему `scout.environment/v1`; код 0 означает полный результат
в документированной области, код 2 — ошибку или неполноту. Это не решение политики.
Режим `--scan` требует полного обнаружения и 1..32 корней; возвращает обычный
отчёт сканирования и его код. Состояния деклараций не устанавливают активность компонентов.

## Флаги scan

### Вход и конфигурация

- `--environment`: явно сопоставить выбранные локальные корни как окружение одного
  агента/проекта; по умолчанию `false`. Обычные входы остаются независимыми.
  Требуются существующие непересекающиеся корни; внешний обход не поддерживается.
  См. [анализ окружения](../user/environment-analysis.ru.md).

- `--config FILE`: явная JSON-конфигурация оператора; по умолчанию не задана.
  Допускается только один раз. Конфигурация не ищется внутри проверяемых целей.
- `--profile standard|review|custom`: профиль проверки; по умолчанию `standard`.
  `standard` выбирает все статические проверки; `review` также требует настроенного
  reviewer; `custom` допускает явный выбор проверок. Aliases CLI: `extended` =
  `standard`, `semantic` = `review`, `basic` = `custom` со всеми отключёнными
  необязательными статическими проверками.
- `--harness auto|claude-code|codex|agent-skills`: интерпретация деклараций агентов
  и плагинов; по умолчанию `auto`.
- `--input -`: читать один вход из stdin; по умолчанию не задан. Поддержан только `-`.
- `--name RELATIVE_PATH`: обязателен с `--input -`; относительное имя файла для
  определения формата и координат исходников. По умолчанию не задано.

Храните конфигурацию, baseline, дополнительные правила и кеши вне всех проверяемых
входов. См. [конфигурацию](../user/usage.ru.md#конфигурация) и
[профили](../user/inspection-profiles.ru.md).
Для типового сценария скопируйте [готовый конфиг](../../examples/configs/README.ru.md).

### Отчёты

- `--format text|json|sarif|markdown`: формат основного отчёта; по умолчанию `text`.
  `terminal` — alias для `text`.
- `--output FILE`: назначение основного отчёта; по умолчанию stdout. Существующий
  обычный файл заменяется атомарно; каталоги и символические ссылки отвергаются.
- `--report FORMAT=PATH`: дополнительный отчёт; повторяемый, по умолчанию отсутствует.
  Форматы совпадают с `--format`. Назначения должны различаться и находиться вне
  проверяемых входов и доверенных файлов оператора. Основной отчёт тоже формируется.

Диагностика идёт в stderr. Создавайте каталоги назначения перед запуском.
См. [сохранение отчётов](../user/usage.ru.md#сохранение-отчётов).

### Политика

- `--fail-on info|low|medium|high|critical`: минимальная серьёзность неподавленной
  находки, блокирующей установку; по умолчанию `high`. Другие причины политики могут
  требовать ручной проверки; неполный запуск по-прежнему возвращает код 2.
- `--block-at SEVERITY`: alias для `--fail-on` с тем же default. Если заданы оба,
  действует последнее указанное значение.
- `--scope conservative|selected`: политика покрытия языков; по умолчанию
  `conservative`. `selected` допускает заявленные ограничения анализа языка,
  но не ошибки разбора, незавершённые проверки или исчерпанные лимиты.
- `--baseline FILE`: доверенный JSON baseline оператора; по умолчанию не задан.
- `--allow-baseline-globs`: разрешить исключения по маске в baseline;
  по умолчанию `false`.

См. [baseline](../user/usage.ru.md#baseline) и
[политику покрытия](../user/inspection-profiles.ru.md#область-проверки).

### Необязательные статические проверки

- `--checks LIST`: полный список необязательных статических проверок через запятую.
  По умолчанию без конфигурации: `python,yaml,toml,yara,patterns`; для alias профиля
  `basic` — `none`. Явный список заменяет набор из конфигурации целиком.
  Имена: `python` — проверки Python AST, `yaml` и `toml` — структурный разбор,
  `yara` — нативные YARA-X-сигнатуры, `patterns` — адаптированные проверки SkillSpector.
  `none` отключает все необязательные статические проверки. Встроенные обязательные
  проверки всегда остаются включёнными. Флаг задаётся один раз; пустые, неизвестные,
  повторяющиеся имена и сочетание `none` с другими именами отвергаются.
- `--yara-rules FILE`: дополнительные доверенные YARA-правила; по умолчанию не заданы.
  Требуют включённого YARA. Include и вывод в консоль запрещены.

Сокращённый список и `none` требуют `--profile custom`; `standard` и `review`
требуют полный набор. Для одних встроенных проверок используйте
`--profile custom --checks none`.
См. [проверки и расширения](../user/inspection-profiles.ru.md).

### Параллелизм и лимиты

- `--workers N`: общие для входов операции workers анализаторов; по умолчанию `4`,
  диапазон 1..32.
- `--target-workers N`: одновременно проверяемые входы; по умолчанию `1`,
  диапазон 1..32.
- `--timeout DURATION`: срок всей операции сканирования или сравнения; по умолчанию
  `2m`, положительный и не больше `10m`.
- `--parser-timeout DURATION`: срок одного разбора парсером; по умолчанию `3s`,
  положительный и не больше `10s`.
- `--max-files N`: захваченные файлы на один вход; по умолчанию `4096`, положительное
  число не больше `--max-entries`.
- `--max-entries N`: элементы инвентаризации на один вход, включая отвергнутые;
  по умолчанию `8192`, диапазон 1..100000.
- `--max-file-bytes N`: байты одного захваченного файла; по умолчанию `1048576`
  (1 МиБ), диапазон 1..33554432.
- `--max-total-bytes N`: захваченные байты на один вход; по умолчанию `33554432`
  (32 МиБ), не меньше `--max-file-bytes` и не больше `268435456`.
- `--max-archive-bytes N`: байты исходного архива на один вход; по умолчанию
  `33554432`, диапазон 1..134217728.
- `--max-capture-bytes N`: суммарные захваченные байты всего запуска; по умолчанию
  `33554432`, диапазон 1..268435456.
- `--max-operations N`: бюджет анализа, общий для входов и заданий; по умолчанию
  `16777216`, диапазон 1..1099511627776.
- `--max-matches-per-rule N`: потолок кандидатов совпадений на анализатор по файлам
  одного входа; по умолчанию `1024`, диапазон 1..100000.
- `--max-findings N`: сохраняемые находки всего запуска; по умолчанию `1024`,
  диапазон 1..100000. Пропуски из-за лимита делают запуск неполным.
- `--extract-depth N`: глубина рекурсивного извлечения; по умолчанию `4`,
  диапазон 1..16.
- `--extract-objects N`: производные объекты на один вход; по умолчанию `256`,
  диапазон 1..4096.
- `--extract-entries N`: посещённые элементы извлечения на один вход; по умолчанию
  `8192`, диапазон 1..100000.
- `--extract-object-bytes N`: байты одного производного объекта; по умолчанию
  `1048576`, диапазон 1..33554432.
- `--extract-total-bytes N`: извлечённые байты на один вход; по умолчанию `16777216`
  (16 МиБ), не меньше `--extract-object-bytes` и не больше `134217728`.

Лимиты одного входа также ограничены общими бюджетами запуска, поделёнными между
входами. В конфигурации дополнительно доступны `limits.max_extracted_bytes`
(по умолчанию 16 МиБ), `limits.max_capture_files` (4096),
`limits.max_capture_entries` (8192) и `limits.max_service_requests` (64);
отдельных CLI-флагов для них сейчас нет. Повышение лимита одного входа не повышает
соответствующий общий бюджет.

### Загрузки

- `--allow-download`: разрешить явную загрузку удалённых входов; по умолчанию `false`.
- `--download-timeout DURATION`: срок одного запроса загрузки; по умолчанию `30s`,
  положительный и не больше `2m`. Используйте с `--allow-download`.
- `--download-allow-loopback`: разрешить явные числовые loopback-адреса загрузок
  и их обычные HTTP URL; по умолчанию `false`. Требует `--allow-download`.
- `--revision SHA`: полный commit SHA из 40 символов для корня GitHub-репозитория;
  по умолчанию не задан. Требует `--allow-download`.
- `--download-sha256 HEX`: ожидаемый SHA-256 всех загруженных байтов, 64
  шестнадцатеричных символа; по умолчанию не задан. Требует `--allow-download`.

Флаги revision/checksum переопределяют соответствующие `remote_pins` конфигурации
для каждого удалённого входа текущего запуска.
См. [внешние источники](external-sources.ru.md).

### Внешние ссылки

- `--follow-external`: захватывать поддержанные буквальные ссылки на внешние
  исходники; по умолчанию `false`. Требует `--allow-download`.
- `--external-origin ORIGIN`: точный разрешённый origin; повторяемый. Задание флага
  заменяет defaults `https://raw.githubusercontent.com` и `https://github.com`.
- `--external-depth N`: максимальное число переходов по ссылкам; по умолчанию `2`,
  диапазон 1..8.
- `--external-max-requests N`: потолок запросов обхода на весь запуск; по умолчанию
  `16`, диапазон 1..64, также ограничен общим бюджетом сервисов.
- `--external-max-bytes N`: суммарные байты ответов обхода; по умолчанию `4194304`
  (4 МиБ), диапазон 1..33554432.

Все флаги `--external-*` требуют `--follow-external`. Разрешённые origins должны
использовать HTTPS, кроме явно разрешённых числовых loopback-адресов.

### Уязвимости

- `--vuln`: включить OSV-запросы по точным координатам;
  по умолчанию `false`. Требует разрешения сети или явного офлайн-кеша.
- `--allow-vulnerability-network`: разрешить запросы координат пакетов отдельно
  от загрузок и передачи исходников; по умолчанию `false`.
- `--osv-cache FILE`: доверенный кеш точных запросов; по умолчанию не задан.
  Путь к кешу также включает сервис. Сейчас `--vuln=false`
  не переопределяет непустой путь к кешу.
- `--osv-cache-max-age DURATION`: максимальный возраст кеша; по умолчанию `168h`
  (7 дней), диапазон `1m`..`8760h`.
- `--osv-endpoint URL`: адрес запросов; по умолчанию
  `https://api.osv.dev/v1/querybatch`.
- `--osv-allow-loopback`: разрешить явный числовой loopback-адрес сервиса;
  по умолчанию `false`.
- `--osv-max-requests N`: потолок запросов, включая ошибки и пагинацию; по умолчанию
  `128`, диапазон 1..256. Общий бюджет сервисов может его уменьшить.

Используйте настройки `--osv-*` с включённым сервисом. Отсутствующие и устаревшие
записи кеша оставляют пробелы проверки.
См. [использование OSV](../user/usage.ru.md#сетевые-сервисы-и-дополнительные-rules).

### LLM-проверка

- `--semantic`: включить reviewer, настроенный флагами; по умолчанию `false`.
  Объект `review` в конфигурации тоже включает сервис. `--semantic=false`
  отключает такой сервис; для отключения также выберите профиль, отличный от `review`.
- `--allow-source-upload`: разрешить передачу захваченных исходников;
  по умолчанию `false`. Требуется любому включённому reviewer, включая локальный.
- `--quality-review`: включить дополнительную оценку качества и политики;
  по умолчанию `false`.
- `--llm-provider chat-completions|anthropic|anthropic-proxy|bedrock`: транспорт
  провайдера; по умолчанию `chat-completions`.
- `--llm-endpoint URL`: явный доверенный адрес reviewer; по умолчанию не задан.
- `--llm-model NAME`: явная модель; по умолчанию не задана.
- `--llm-api-key-env NAME`: переменная окружения с API-ключом; по умолчанию не задана.
  Автопоиска учётных данных нет. Используется для провайдеров кроме Bedrock.
- `--llm-aws-region REGION`: регион Bedrock; по умолчанию не задан.
- `--llm-aws-access-key-env NAME`: переменная с access key Bedrock;
  по умолчанию не задана.
- `--llm-aws-secret-key-env NAME`: переменная с secret key Bedrock;
  по умолчанию не задана.
- `--llm-aws-session-token-env NAME`: необязательная переменная с session token
  Bedrock; по умолчанию не задана.
- `--llm-allow-loopback`: разрешить явный числовой loopback-адрес reviewer;
  по умолчанию `false`.
- `--llm-max-output-tokens N`: запрошенный потолок токенов ответа;
  по умолчанию `2048`, диапазон 128..8192.
- `--llm-max-response-bytes N`: потолок байтов HTTP-ответа провайдера;
  по умолчанию `65536` (64 КиБ). Он не повышает отдельный бюджет декодированного
  ответа reviewer.
- `--llm-max-requests N`: бюджет запросов, общий для проходов; по умолчанию `64`,
  диапазон 1..256. Общий бюджет сервисов может его уменьшить.
- `--llm-max-input-bytes N`: суммарные байты сериализованных пользовательских
  запросов; по умолчанию `2097152` (2 МиБ), диапазон 32768..8388608.
- `--llm-timeout DURATION`: срок одного запроса провайдеру; по умолчанию `30s`,
  положительный и не больше `2m`, также ограничен сроком всей операции.

Настройки провайдера и качества требуют включённого reviewer. `--profile review`
по-прежнему требует `--semantic`, если reviewer задаётся только флагами.
См. [семантическую проверку](../user/semantic-review.ru.md) для условий согласия
и требований провайдеров.

## Сравнение

`compare` требует ровно два локальных пути. Поддерживает флаги конфигурации,
отчётов, политики, проверок, параллелизма, лимитов, OSV и reviewer из `scan`.
Отвергает `--input`, `--name`, `--allow-download`, `--revision`, `--download-*`,
`--follow-external` и `--external-*`.

- `--max-changes N`: максимум сохраняемых изменений сравнения; по умолчанию
  `4096`, диапазон 1..20000. Усечение делает сравнение неполным.

Тайм-аут и общие бюджеты охватывают оба сканирования и сравнение.
См. [сравнение обновлений](../user/update-review.ru.md).

## Валидация конфигурации

`config validate` использует флаги конфигурации, политики, статических проверок,
параллелизма, лимитов и сервисов из `scan`, чтобы создать и проверить Scanner
без входов. `--config FILE` необязателен; без него проверяются defaults.
Результат — подготовленный план проверки, всегда в JSON в stdout.
Флаги отчёта сканирования (`--format`, `--output`, `--report`) не управляют этим выводом.

## Сервер MCP

`mcp` использует флаги конфигурации, политики, статических проверок, параллелизма,
лимитов и сервисов из `scan`. Входы разрешаются через `--target` или передаются
загрузкой инструмента; `--input`/`--name` не выбирают сканирование stdin.
Флаги отчётов сканирования не управляют выводом протокола.

- `--transport stdio|http`: транспорт; по умолчанию `stdio`.
- `--listen ADDRESS`: числовой loopback-адрес HTTP-сервера; по умолчанию
  `127.0.0.1:8837`.
- `--auth-token-env NAME`: переменная окружения с HTTP bearer token;
  по умолчанию не задана. Обязательна для HTTP; токен содержит 32..512 байтов
  без пробельных символов.
- `--scan-timeout DURATION`: срок каждого допущенного вызова инструмента;
  по умолчанию `1m`, положительный и не больше `10m`. `--timeout` также
  ограничивает операцию Scanner.
- `--max-concurrent N`: параллелизм вызовов инструмента между сессиями;
  по умолчанию `2`, диапазон 1..8.
- `--target NAME=LOCAL_PATH`: разрешённый именованный локальный вход; повторяемый,
  по умолчанию отсутствует, максимум 64. Клиент инструмента выбирает имя вместо
  произвольного пути.
- `--origin ORIGIN`: явно разрешённый браузерный HTTP Origin; повторяемый,
  по умолчанию отсутствует. Пустой список запрещает браузерные origins. Только для HTTP.

`--auth-token-env` тоже предназначен только для HTTP. Без именованных целей
используйте загрузку содержимого.
См. [настройку MCP](../user/integrations.ru.md#mcp-server).

## Doctor

`doctor` (alias `selftest`) проверяет подключённые нативные движки.

- `--format text|json`: формат; по умолчанию `terminal`, alias для `text`.
- `--timeout DURATION`: кооперативный срок всей самопроверки; по умолчанию `90s`,
  положительный и не больше `2m`.

## Baseline

Обе команды `baseline create` и `baseline approve` принимают:

- `--from FILE`: обязательный источник. `create` читает валидированный JSON-отчёт
  с одним входом; `approve` — JSON-документ baseline.
- `--output FILE`: обязательное назначение; не должно заменять источник.
- `--reason TEXT`: обоснование оператора; по умолчанию не задано, обязательно
  для непустых baseline.
- `--expires RFC3339`: обязательный будущий срок, например `2099-01-01T00:00:00Z`.

`create` пишет неодобренные записи. `approve` одобряет все записи выбранного
документа. См. [работу с baseline](../user/usage.ru.md#baseline).

## Правила, профили и возможности

- `rules list --all`: включить метаданные адаптированных, Python- и YARA-правил;
  по умолчанию `false`. Без `--all` выводится базовый каталог. Формат — JSON.
- `profiles`: JSON-список имён профилей; без флагов.
- `capabilities`: JSON о подключённых движках парсеров и сигнатур; без флагов.
- `version`: текстовая версия сборки; без флагов. Корневой `--version` эквивалентен.

## База знаний и интеграции

`knowledge` по умолчанию печатает встроенный каталог в JSON.

- `--mode discovery|intent|tool_consistency|assessment|proposal_assessment|quality`:
  вывести точный доверенный runtime-промпт выбранного режима;
  по умолчанию режим не задан.

`integrations list` выводит манифесты пакетов в JSON без флагов.
`integrations export` принимает:

- `--bundle agent-skill|claude-code|codex|pi|opencode|review-materials`: обязательное
  имя пакета; по умолчанию не задано.
- `--output FILE`: обязательный новый ZIP-путь. Существующие файлы не заменяются.

См. [интеграционные пакеты](../user/integrations.ru.md).

## Registry

`registry fetch` не принимает позиционных входов и поддерживает:

- `--endpoint URL`: адрес servers реестра; по умолчанию
  `https://registry.modelcontextprotocol.io/v0/servers`.
- `--name NAME`: точное имя сервера; отсутствие означает все имена.
- `--latest`: выбирать записи, заявленные реестром как latest для имени;
  по умолчанию `false`.
- `--allow-download`: разрешить запросы реестра; по умолчанию `false`.
- `--allow-loopback`: разрешить числовой loopback-адрес тестового реестра;
  по умолчанию `false`.
- `--max-pages N`: потолок страниц; по умолчанию `32`, диапазон 1..128.
- `--max-bytes N`: суммарные байты ответов; по умолчанию `8388608` (8 МиБ),
  диапазон 1..33554432.
- `--output FILE`: назначение JSON-снимка; по умолчанию stdout.

`registry compare` принимает два пути снимков: предыдущий и текущий.

- `--output FILE`: назначение JSON-сравнения; по умолчанию stdout.

См. [снимки реестра](external-sources.ru.md#mcp-registry).

## Проверка аттестации

`attestation verify` требует все четыре флага, по умолчанию не заданные:

- `--public-key FILE`: явный доверенный PKIX public key PEM вне проверяемых входов.
- `--envelope FILE`: DSSE envelope или OMS bundle.
- `--artifact FILE`: обычный файл артефакта, чьи точные байты должны соответствовать подписи.
- `--subject NAME`: точное имя подписанного subject.

См. [проверку подписей](external-sources.ru.md#проверка-dssein-toto).

## Коды завершения

Для сканирования и сравнения: `0` — полный запуск и allow; `1` — полный запуск
с review или block; `2` — неполнота, отмена, неверный запрос или ошибка записи.
Доступные отчёты полезны и при ненулевом коде завершения.

Для проверки аттестации: `0` — соответствие; `1` — несовпадение подписи или subject;
`2` — неверные входы или операционная ошибка. Doctor возвращает `2` при провале
нативной самопроверки. Другие операторские команды используют `0` для успеха
и `2` для ошибки.
