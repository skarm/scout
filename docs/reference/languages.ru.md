# Языки и форматы конфигурации

[English](languages.md) · Русский

Scout анализирует захваченный код, блоки Markdown и поддерживаемые вложения,
не запуская проверяемые программы. Доступные движки показывает `scout capabilities`.

## Go

`go/parser` строит AST без импорта проверяемых пакетов. GO001–GO006 проверяют
построение команд оболочки, чувствительные файлы, выбранные потоки учётных данных в HTTP,
динамический SQL и отключённую проверку TLS. Учитываются псевдонимы и локальное
затенение; общего разрешения типов и полного графа вызовов нет.

## Python

Полная сборка использует Tree-sitter и ограниченное преобразование конкретного
синтаксического дерева (CST) в промежуточное представление (IR), без среды Python.
Проверки охватывают выбранные операции с процессами, `eval` и импортом,
чувствительные файлы, сетевые аргументы, десериализацию, восстановление значений и локальные потоки.
Неподдержанные конструкции и неразрешимые потоки остаются пробелами проверки.

## Shell

Ограниченный парсер проверяет конвейеры, присваивания, перенаправления, подстановки и отдельные ветвления. `mvdan.cc/sh/v3/syntax` предоставляет декларации команд и подключений. `SH001`–`SH004` проверяют выполнение загруженного кода, токены в запросах, возможности выполнения и чтение чувствительных данных. Динамические аргументы и неподдерживаемый поток управления оставляют пробелы.

### Хуки и локальные обработчики

Scout читает поддерживаемые события из `hooks.json`, локальных файлов по ссылкам из манифеста и настроек проекта Claude в `.claude/settings.json` или `.claude/settings.local.json`. Хуки проекта Claude можно проверить без манифеста плагина. В расширениях Gemini Scout ищет `hooks/hooks.json` рядом с `gemini-extension.json`. [Хуки Claude Code](https://code.claude.com/docs/en/hooks) · [Расширения Gemini CLI](https://geminicli.com/docs/extensions/reference/)

Трассировка следует за фиксированными строками команд, явными аргументами интерпретатора и разрешёнными локальными запусками, включая `source` и `.`. Отчёт указывает событие, путь вызова или подключения и исходные байты. Для относительного пути нужен известный рабочий каталог. Путь в кавычках от корня может разрешиться внутри захваченного пакета. Для корня без кавычек Scout может показать предполагаемый обработчик с `hook_source_unquoted_root`. Подстановка Gemini тоже может оставить пробел, если путь установки неизвестен.

Для отдельных присваиваний, вызовов, ветвлений, циклов, подстановок и числовых проверок Scout сохраняет статически известные значения. Неоднозначные или динамические команды, пути, аргументы интерпретатора, записи и изменения поиска команд могут оставлять пробелы. В отчёте текст команд Bash, POSIX Shell и PowerShell `-Command` отделён от подключения файлов. `SH003` также отмечает явные вызовы `npm run` в захваченных обработчиках.

### Сгенерированные скрипты

Scout восстанавливает поддерживаемые записи heredoc через `cat` и `tee` и проверенные данные на stdin оболочки. Тип Shell определяется по имени файла, shebang или моделируемому использованию. Восстановление охватывает до четырёх поколений в общем бюджете. Находки ссылаются на содержащий файл или элемент архива, включая места подстановок.

`SH005` связывает восстановленную запись с последующим использованием в Shell через поддерживаемые дописывания, переименования и смены каталога. В ходе трассировки хуков Claude оно также отмечает поддерживаемые перенаправления в `CLAUDE_ENV_FILE`. Неизвестный путь или базовая версия при дописывании могут вызвать `generated_shell_dynamic_path` или `generated_shell_append`. Неизвестные эффекты могут сбросить ранее установленные связи.

## JavaScript и TypeScript

Полная сборка использует официальные грамматики Tree-sitter. `JS001`–`JS006` проверяют запуск команд, динамическое вычисление, токены в сетевых аргументах, динамический SQL, чувствительные файлы и отключение проверки TLS. Анализ учитывает отдельные импорты ESM и CommonJS, псевдонимы, деструктуризацию, затенение имён и ветвления. Неподдерживаемые потоки оставляют пробелы. В core-сборках и сборках без CGO грамматики недоступны.

Если хук ведёт к захваченному исходнику, Scout может связать поддерживаемые вызовы процессов Node с этим хуком. Он также анализирует литеральные программы `node -e` и `python -c`, а также Python в heredoc с разделителем в кавычках. Находки ссылаются на программу и вызвавший её хук. Полный статический охват возможен для отдельных изолированных запусков `python3 -I -S`, например для литерального преобразования JSON с ограниченными входами. Динамическое разрешение модулей и поведение при запуске могут оставлять пробелы. [Процессы Node](https://nodejs.org/api/child_process.html) · [Параметры Python](https://docs.python.org/3/using/cmdline.html#cmdoption-I)

## SQL

Go-парсер работает в core-сборке. SQL001–SQL004 проверяют выбранные разрушительные
операции, изменения полномочий и защиты на уровне строк (RLS), серверный ввод-вывод файлов и программ,
отключение лимитов. Комментарии, строки и идентификаторы различаются.
Процедурные тела в строках с долларовыми разделителями не поддерживаются. SQL-интерполяция Go и JS/TS
проверяется на AST соответствующего языка.

## Markdown

Goldmark разбирает контейнеры блоков CommonMark: вложенные списки, цитаты,
ограждённый код и код с отступами. После удаления префиксов контейнеров Scout
сохраняет LF, CRLF и координаты исходных байтов. Одиночный CR преобразуется
в LF для анализа. Для кода с отступами без метки используются
только существующие узкие признаки языка; неизвестный язык остаётся пробелом.
Ограждённый код внутри HTML-блоков проверяется отдельным ограниченным проходом
по исходному содержимому. Семантика HTML и среды выполнения не поддерживается.
Рендеринг и загрузка ссылок не выполняются. Лимиты: 1 МиБ на вход Markdown,
2 МиБ суммарных байтов разбора с HTML-проекциями, 64 уровня контейнеров, 8192 узла
блоков, 512 областей, 8192 сегмента карты исходников и 256 КиБ на представление кода.
При отмене или исчерпании лимита сохраняются доступные блоки и проверки исходного
текста, а покрытие становится неполным.

## Конфигурации

При разборе JSON проверяются повторяющиеся декодированные ключи. Полная сборка
предоставляет разбор YAML и TOML общего назначения. Core-сборка также разбирает
конфигурации TOML для Codex, Grok и Kimi Code и YAML DeepSeek Cordis в известных
расположениях. Псевдонимы, слияния и пользовательские теги YAML не поддерживаются.
Указанное место в TOML охватывает всю единицу разбора.
Успешный разбор не доказывает совместимость со всеми загрузчиками приложений.

## Область проверки

Межфайловые потоки используют выбранные захваченные импорты и функции:
[проверки потоков](hardening-2026-10-29.ru.md#потоки-данных).
Ошибки разбора, неподдержанные формы и исчерпанные лимиты остаются видимыми пробелами.
`complete` относится к выбранным проверкам; [область политики](../user/inspection-profiles.ru.md#область-проверки)
определяет отношение к заявленным языковым ограничениям.
