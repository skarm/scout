# Языки и форматы конфигурации

[English](languages.md) · Русский

Scout анализирует захваченный код, блоки Markdown и поддерживаемые вложения,
не запуская проверяемые программы. Доступные движки показывает `scout capabilities`.

## Go

`go/parser` строит AST без импорта проверяемых пакетов. GO001–GO006 проверяют
построение команд оболочки, чувствительные файлы, выбранные потоки учётных данных в HTTP,
динамический SQL и отключённую проверку TLS. Учитываются псевдонимы и локальное
затенение; общего разрешения типов и полного графа вызовов нет.

## Python

Полная сборка использует Tree-sitter и ограниченное преобразование конкретного
синтаксического дерева (CST) в промежуточное представление (IR), без среды Python.
Проверки охватывают выбранные операции с процессами, `eval` и импортом,
чувствительные файлы, сетевые аргументы, десериализацию, восстановление значений и локальные потоки.
Неподдержанные конструкции и неразрешимые потоки остаются пробелами проверки.

## Shell

Ограниченные деревья команд охватывают конвейеры, присваивания, перенаправления
и подстановки. `mvdan.cc/sh/v3/syntax` отдельно разбирает декларации команд
и источников. SH001–SH004 проверяют выполнение загруженного кода, учётные данные
в запросах, возможности `eval`, `source` и оболочки, а также чтение чувствительных данных.
Учитываются выбранные параметры curl/wget и происхождение сохранённых файлов.
Динамические аргументы и неподдержанные конструкции управления ограничивают полноту.

Scout восстанавливает записи heredoc через `cat` и `tee` по относительному пути.
Признаком shell-скрипта служит расширение `.sh`, shell-shebang или последующее
использование того же файла через оболочку, `source`, `.` или прямой запуск
по явному пути. Для прямого запуска файлов без `.sh` shebang другой среды
исключает shell-анализ. Обычные файлы и восстановленные скрипты используют один
разбор shebang. Поддерживаются фиксированный путь к интерпретатору и простые
формы `env` и `env -S`. Scout также анализирует проверенный heredoc на stdin
оболочки напрямую или через простой `cat | sh`, который передаёт тело без
изменений. Восстановление работает внутри поддерживаемых блоков, функций,
конвейеров с явным вводом и файлов из архивов. Простые параметры разрешаются по предыдущим
однозначным присваиваниям. Общие лимиты действуют на все четыре уровня
вложенной генерации. Находки сохраняют байты и строки исходного файла
или элемента архива. Для подставленного текста указывается место ссылки на
параметр. Вызовы функций, ловушки, изменения `PATH` и таблицы `hash`
могут сделать команду записи или её вход неоднозначными. Для статически
разрешимых вызовов локальных функций Scout учитывает переменные и состояние
поиска команд в каждой точке вызова, в том числе простые временные присваивания
и известные позиционные аргументы, например `$1` и `${10}`.
Поздние изменения `PATH` или `hash` не влияют на более ранний разрешимый вызов.
Для функций без установленных вызовов и неоднозначных вызовов используются
консервативные сведения по всему файлу. Рекурсия, неразрешимые подстановки,
неоднозначная команда и исчерпание лимитов оставляют пробел покрытия.

Распознаваемая запись shell-скрипта по неразрешимому пути, например `"${name}.sh"`,
получает диагностику `generated_shell_dynamic_path`. Scout объединяет поддерживаемые
записи через `>>` и `tee -a`/`--append` с последней известной полной версией
скрипта. Каждый фрагмент сохраняет свои исходные координаты. При неизвестном
начальном содержимом или промежуточной записи остаётся `generated_shell_append`.
Диагностики указывают исходную строку и столбец, когда их можно определить.
Общий пробел восстановления сопровождается конкретной причиной. Полностью
неизвестный путь без признаков shell-скрипта остаётся за пределами этой проверки.

Информационная находка SH005 связывает запись, тело heredoc и последующий
`source`, `.`, запуск через оболочку или по явному пути в одной отслеживаемой
последовательности команд, включая прямые вызовы локальных функций. Анализ
учитывает разрешимый `cd`, простое переименование через `mv` между двумя
локальными путями и последнюю запись по каждому пути. В трассе видны исходная
запись, дописывания, переименования и вызов. После `if`/`elif`/`else` связь
сохраняется, когда на всех продолжающихся путях совпадают рабочий каталог,
версия файла и её исходные координаты. Длинные цепочки дописываний и
переименований могут исчерпать лимит трассировки при сохранении анализа
содержимого. Неоднозначная смена каталога, перезапись и команды с неизвестными
эффектами сбрасывают прежнюю связь. Пути сравниваются лексически. Типы файлов,
права и успех команд во время выполнения не проверяются. Для `source` и `.`
используется явный путь, чтобы исключить поиск по каталогам.

## JavaScript и TypeScript

Полная CGO-сборка использует официальные грамматики Tree-sitter. JS001–JS006 проверяют
API оболочки, динамическое выполнение кода, учётные данные в сетевых аргументах, динамический SQL,
чувствительные файлы и отключённую проверку TLS. Учитываются выбранные ESM/CommonJS
псевдонимы, деструктуризацию, затенение, перезаписи и ветвления.
Неподдержанные конструкции управления оставляют пробелы. Сборки core/no-CGO сообщают о недоступности грамматик.

## SQL

Go-парсер работает в core-сборке. SQL001–SQL004 проверяют выбранные разрушительные
операции, изменения полномочий и защиты на уровне строк (RLS), серверный ввод-вывод файлов и программ,
отключение лимитов. Комментарии, строки и идентификаторы различаются.
Процедурные тела в строках с долларовыми разделителями не поддерживаются. SQL-интерполяция Go и JS/TS
проверяется на AST соответствующего языка.

## Markdown

Goldmark разбирает контейнеры блоков CommonMark: вложенные списки, цитаты,
ограждённый код и код с отступами. После удаления префиксов контейнеров сохраняются
LF/CRLF и координаты исходных байтов. Для кода с отступами без метки используются
только существующие узкие признаки языка; неизвестный язык остаётся пробелом.
Ограждённый код внутри HTML-блоков проверяется отдельным ограниченным проходом
по исходному содержимому. Семантика HTML и среды выполнения не поддерживается.
Рендеринг и загрузка ссылок не выполняются. Лимиты: 1 МиБ на вход Markdown,
2 МиБ суммарных байтов разбора с HTML-проекциями, 64 уровня контейнеров, 8192 узла
блоков, 512 областей, 8192 сегмента карты исходников и 256 КиБ на представление кода.
При отмене или исчерпании лимита сохраняются доступные блоки и проверки исходного
текста, а покрытие становится неполным.

## Конфигурации

При разборе JSON проверяются повторяющиеся декодированные ключи. YAML и TOML требуют движков полной
сборки. Псевдонимы, слияния и пользовательские теги YAML не поддерживаются.
Байтовые интервалы TOML могут охватывать всю единицу разбора.
Успешный разбор не доказывает совместимость со всеми загрузчиками приложений.

## Область проверки

Межфайловые потоки используют выбранные захваченные импорты и функции:
[проверки потоков](hardening-2026-10-29.ru.md#потоки-данных).
Ошибки разбора, неподдержанные формы и исчерпанные лимиты остаются видимыми пробелами.
`complete` относится к выбранным проверкам; [область политики](../user/inspection-profiles.ru.md#область-проверки)
определяет отношение к заявленным языковым ограничениям.
