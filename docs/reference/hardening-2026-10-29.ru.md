# Скрытое содержимое, потоки данных и инструменты

[English](hardening-2026-10-29.md) · Русский

Выбор проверок зависит от [профиля](../user/inspection-profiles.ru.md).
Описания доступны через `scout rules list --all`.

## Скрытое содержимое

Unicode Tags и поддержанные variation-selector payloads декодируются и проверяются
с координатами носителя. Исходные байты сохраняются. Повторяющиеся selectors могут
дать `NV-AE7` и при ошибке декодирования; одиночного emoji selector недостаточно.

`HI001` связывает скрытые HTML/comments с инструкциями override, передачи секретов
или выполнения. `RX001` проверяет чувствительные подстановки в Markdown и HTML
image/link URLs. Пометки документации и fences не подавляют доказательства.

## Потоки данных

`SH001` связывает curl/wget download с pipe/string execution или последующим запуском
сохранённого файла. Учитываются выбранные redirects, cp/mv, cat/stdin, shell/source
и формы Python/Node. Безусловная локальная перезапись снимает прежнее происхождение;
`bash -n` не считается выполнением.

`XF001` связывает чувствительное чтение с network APIs, скачанный body — с execution
APIs через выбранные imports/functions Python, JS/TS и Go. Учитываются параметры,
возвраты, assignments, globals и выбранные transforms. Related evidence сохраняет
идентичность файлов и исходные интервалы.

Строковые литералы с выбранными формами провайдерских токенов также считаются
источниками чувствительных данных для `XF001` и `DNS001` в исходных файлах JS/TS,
Python, Go и блоках Markdown. Используются общие с `SE002`–`SE007` грамматики,
границы токенов, исключения заглушек и фильтр энтропии. Алиасы, локальные вызовы и
выбранные преобразования сохраняют исходный интервал литерала, включая поддержанные
escape-последовательности. Безусловная перезапись публичным значением очищает
происхождение этой привязки; независимые алиасы сохраняют своё происхождение.
Методы преобразования сохраняют происхождение без предположения о вычисленном
значении адреса. Классификация выполняется один раз на узел с учётом размера
декодированного литерала в общем лимите операций. Отдельно собранные фрагменты токена
и декодирование нераспознанного закодированного токена в секрет остаются вне модели
источников. Значения не проверяются через провайдеров и не попадают в сообщения находок.
Результат функции задают явный возврат и тело-выражение стрелочной функции JS/TS.
Объявления, проверки assert, аннотации, выражения без возврата и строки документации
Python не становятся возвращаемыми значениями. Безусловный возврат в поддержанном
вложенном блоке останавливает этот путь функции; предыдущие наблюдения сохраняются.
Условные возвраты остаются неразрешёнными: результат функции неизвестен, анализ
сохраняет явный пробел проверки. После объединения привязок строка остаётся известной
только при совпадении наблюдаемых вариантов; разные строки не сохраняют прежний hostname.
Перезапись с потерей происхождения в условных ветках плоской проекции также оставляет
явный пробел проверки вместо отрицательного результата с отметкой о завершении анализа.
Условные алиасы API с разными символическими именами остаются неразрешёнными,
не сохраняя прежний API-кандидат.
При расширении цепочки вызовов создаётся независимый срез: последующие вызовы и
объединения кешированных значений не переписывают доказательства прежнего значения.

`DNS001` (High) связывает чувствительные значения окружения, выбранные литералы
провайдерских токенов или чтение файлов учётных
данных с именем DNS-запроса. Поток может находиться в одном файле или проходить через
те же захваченные локальные вызовы, что поддерживает `XF001`. Выбранные конкатенации,
шаблоны и кодировки сохраняют происхождение. Bundle-проекция охватывает исходные файлы
JS/TS, Python, Go и блоки Markdown; shell также поддерживает блоки кода.
У каждого блока отдельные переменные и функции; блоки не входят в Go-пакеты исходных
файлов. Явные локальные imports могут разрешаться в захваченные исходные модули того же
namespace. Evidence сохраняет координаты байтов и хеши исходного Markdown.
Поддерживаются lookup/resolve API
Node `dns`/`dns/promises`, Python `socket.getaddrinfo` (включая `host=`),
`gethostbyname`/`gethostbyname_ex`, запросы имён Go `net.Lookup*` и `net.DefaultResolver`,
а также ограниченные одиночные запросы shell-команд `dig`, `host` и `nslookup`.
В Go SRV компоненты service/protocol/name все входят в запрашиваемое имя.
Shell поддерживает выбранные формы `base64` со stdin; файловые операнды не разрешаются.
Обычный lookup и секрет в другом аргументе API не устанавливают такой поток.
Межфайловые DNS-потоки дополнительно сохраняют evidence `XF001`.

Привязка аргументов Python-helper учитывает positional-only, keyword-only и обязательные
параметры; некорректный вызов или раскрытие аргументов оставляют пробел проверки.
Значения пропущенных параметров с defaults остаются неизвестными; динамические
выражения defaults также оставляют явный пробел bundle-анализа.
`Buffer.from` передаёт происхождение аргумента данных, а не параметров кодировки/смещения.
Shell сохраняет префиксы опций и серверов через подстановку поддерживаемых форм
`printf` и `echo` с одним аргументом, не принимая такие значения за имя запроса.

Выбранные экземпляры распознаются по Node `new dns.Resolver()` / promises-конструкторам,
Go `new(net.Resolver)`, литералам значений/указателей и объявлениям нулевого значения,
а также dnspython `dns.resolver.Resolver` / `dns.asyncresolver.Resolver`. Простые алиасы
и возвраты локальных фабрик сохраняют идентичность. Методы запросов учитывают только
компоненты имени; настройки и тип записи не становятся данными запроса. Простые
параллельные присваивания Go вычисляют все правые части до изменения привязок. Эти формы
также поддерживаются в изолированных блоках Markdown.

Замена метода через алиас инвалидирует идентичность resolver. Динамические свойства,
неопределённые значения получателя и отвязанные методы Node оставляют пробелы.
Связанные методы Go/Python сохраняют получателя. Поддерживаются выбранные setters/поля
конфигурации; собственные Go dialers остаются неразрешёнными. Сложные цепочки и распаковка
присваиваний Python, присваивания и итераторы с распаковкой JS/TS, а также удаление
через JS/TS `delete` и Python `del` останавливают этот путь до использования устаревших
привязок; предыдущие наблюдения сохраняются. Объявления JS/TS с распаковкой сбрасывают
свои привязки в неизвестные значения. При обычной записи в атрибут Python сначала
вычисляется правая часть; аннотация без значения не перезаписывает привязку или метод.
Простая аннотация локального имени скрывает внешнюю привязку во всей функции.
Python global/nonlocal и перепривязка Go resolver
также останавливают неподдерживаемое изменение состояния между копиями кадров.
Изменения классов/prototype resolver остаются неразрешёнными. Состояние импортированных
модулей и Go default resolver сбрасывается для каждого блока с общим лимитом операций;
неподдерживаемая запись в одном блоке не влияет на следующий.
Сканер не загружает и не вызывает resolver-библиотеки
или DNS-утилиты.

Shell batch/reverse/multiple-query и неизвестные опции остаются за пределами модели DNS.
Динамическое имя оставляет результат неполным даже при
найденном потоке чувствительных данных. Во время сканирования DNS-вызовы не выполняются.
Находка не доказывает выполнение, корректную DNS-кодировку, передачу данных или злой
умысел: системный resolver может использовать кэш или локальный hosts-файл.
Позиции аргументов сверены с [Node DNS API](https://nodejs.org/api/dns.html),
[Python socket API](https://docs.python.org/3/library/socket.html),
[Go net API](https://pkg.go.dev/net) и [руководствами BIND](https://bind9.readthedocs.io/en/v9.20.0/manpages.html).
Выбранные методы dnspython сверены с документацией [resolver](https://dnspython.readthedocs.io/en/stable/resolver-class.html)
и [async resolver](https://dnspython.readthedocs.io/en/stable/async-resolver-class.html).

Рекурсия, глубина, неоднозначные exports и исчерпанные квоты оставляют пробелы.
Ограниченный resolver поддерживает JS/TS arrow functions уровня модуля с простыми
параметрами-идентификаторами, телом-блоком или выражением, named/default exports,
локальными aliases экспорта и namespace imports. Default-выражение сохраняет значение
на момент export; export clauses и именованные default declarations следуют за локальной
привязкой. Вложенные замыкания, параметры с defaults/destructuring/rest, re-exports
и значения class/generator остаются неразрешёнными. Условные/составные значения функций
и циклическая инициализация модулей также оставляют пробелы, как и spread-аргументы
вызовов, свойства функций вроде call/bind и динамические свойства namespace. Скобки,
await и выбранные TS assertions сохраняют проецируемое значение без проверки типов.
Это статический анализ потоков, а не выполнение модулей.

Объявления JS/TS скрывают кандидаты встроенных API до инициализации и при неразрешённом
значении. Привязки блоков остаются локальными; объявления внутри функции скрывают привязки
модуля, а `var` без инициализатора не стирает параметр. Sequence expressions сохраняют
только последнее значение. Результаты конструкторов, замыкания с захватом из блока,
объявления функций в блоках, destructured bindings, тела методов, свойства контейнеров
с функциями и условные/вложенные в блок возвраты остаются неразрешёнными. Нелокальная
запись из вызываемой функции останавливает это вычисление bundle до чтения устаревшего
глобального состояния другим кадром; ранее собранные наблюдения сохраняются. При
гипотетической отдельной проверке функции этот пробел сохраняется, но независимая
проверка модулей продолжается. Исчерпание привязок или глубины проекции/выражений
останавливает дальнейшее вычисление;
замена существующей привязки не требует дополнительного места.
Простые параметры catch, блоки switch и лексические initializers `for` имеют свою область видимости.
Значения итератора `for-in`/`for-of` остаются неразрешёнными и не используют скрытое
значение внешней переменной.
Неоднозначное значение функции/модуля не сохраняет прежний namespace для разрешения свойств.
Обращение к свойству неизвестного объекта не создаёт имя глобального API; выбранные
методы чтения чувствительного файла сохраняют исходное происхождение данных.
Неразрешённый/пустой module specifier сохраняет неизвестную привязку импорта, не создавая
из её локального alias имя глобального API.
Сбой инициализации модуля сохраняется: частичные globals и exports не используются
как завершённое состояние при продолжении независимой проверки функций.
После терминальной ошибки дочернего вычисления внешний вызов не создаёт поток из
частично вычисленных аргументов. Наблюдения, завершённые до остановки, сохраняются.

## Сеть и возможности

`NET001` сравнивает HTTP hosts и литеральные имена DNS-запросов с видимыми объявлениями
ближайшего SKILL.md namespace. Нормализуются регистр, конечная точка и IP;
чужие суффиксы не совпадают. Comments, hidden HTML и frontmatter не объявляют hosts.
Неразрешимый динамический адрес оставляет пробел проверки.

`SC004` отмечает npm lifecycle hooks и Python build/setup entry points,
сохраняя related evidence для захваченных локальных handlers. Отдельные проверки
цепочки поставки охватывают mutable sources и registry overrides.

`TC001` отмечает совпадения имён в захваченных JSON tool collections.
`TC002` отмечает чувствительный доступ и сетевые возможности в одном ближайшем
skill scope. Выбранные литералы токенов также добавляют наблюдение о чувствительных данных.
Декларации требуют интерпретации, но не доказывают выполнение или передачу данных.

## Встроенные сигнатуры

YARA-X содержит адаптированные правила SkillSpector и Cisco. Scout назначает
серьёзность по доказательствам и сохраняет сильные witnesses перед слабыми hits.
Усечение оставляет неполноту. Упоминания, отдельные опасные действия и поддержанные
цепочки выполнения получают разные уровни. См. [источники и адаптации](port-manifest.ru.md).
