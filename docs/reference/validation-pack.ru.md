# Инструкции проверки и пояснения

[English](validation-pack.md) · Русский

Материалы `knowledge/` встраиваются при сборке. Проверяемый пакет не может
подменить инструкции или выбрать политику. См. [режимы проверки](../user/semantic-review.ru.md#режимы).

## Протокол

`review.ProtocolVersion` задаёт версию протокола, `review.PromptVersion` — метку
совместимости инструкций.
`review.PromptForRequest` проверяет режим, схему и идентичность инструкций до передачи.
Байты входа остаются пользовательскими данными отдельно от доверенных системных инструкций.

Ответы используют встроенные причины своего режима и ссылки на фрагменты текущего запроса.
`prompt_sha256` обязателен. Хеш уровня отчёта обозначает пакет инструкций;
каждое задание хранит хеш и размер своей инструкции.

`MaxInputBytes` и `RequestBytes` считают сериализованные пользовательские запросы.
Системные инструкции, схема и оболочка провайдера учитываются отдельно.
Оба прохода семантической проверки используют общий лимит.

## Статические пояснения

`knowledge/data/patterns.json` хранит дополнительные выражения и источники адаптаций.
Распознавание выполняют анализаторы; хеши материалов не описывают всю реализацию.

Пояснения включают причины риска, рекомендации, вопросы для проверки, допустимые контексты
и связи с источниками. Контекст помогает интерпретации без подавления находок.
Собственные правила указывают локальные источники; адаптированные сохраняют сведения о происхождении.

JSON содержит полные пояснения. Терминальный вывод и Markdown показывают объяснения
и рекомендации по исправлению; SARIF — справку и свойства источников.
Текст берётся из встроенного набора Scout.
См. [манифест источников](port-manifest.ru.md) и [проверки использования знаний](knowledge-runtime.ru.md).

## Метки версий и хеши

Метки набора знаний, инструкций и комплекта интеграций определены в одном месте:
[`internal/reviewpack/version.go`](../../internal/reviewpack/version.go).
`knowledge.Version` и `review.PromptVersion` остаются публичными константами Go.
Метки независимы от версии Scout и от версий протоколов и JSON-схем.
Суффикс `v4` унаследован от предварительной версии; доступная история Git не подтверждает
последовательность четырёх выпусков.

Точное содержимое определяют SHA-256 набора, отдельных инструкций и файлов
комплекта. При изменении содержимого хеш меняется автоматически. Метку меняют
при изменении соответствующего контракта совместимости, а не при каждой правке текста.

При экспорте `.scout-bundle.json` и `transfer-manifest.json` получают одну текущую
версию комплекта. Поле `adaptation_version` в `transfer-manifest.json` сохраняет
историческую метку исходной адаптации; старые записи происхождения
не описывают текущий комплект.
