# Нативная сборка

[English](native-build.md) · Русский

Нужны Go 1.26+, компилятор C, `make` и `pkg-config`. Автоматическая подготовка
поддержана для macOS 15+ на Apple Silicon и GNU/Linux на ARM64 или x86-64.
Rust и Homebrew не требуются.

## Сборка и приёмка

```sh
make deps
make build
./bin/scout doctor --format json
make releasecheck
```

Make скачивает закреплённый пакет YARA-X C API 1.22.0, проверяет SHA-256 и сохраняет
его в пользовательском кеше. Tree-sitter и привязки Go приходят из закреплённых
модулей Go. `releasecheck` проверяет компоновку, метаданные модулей и нативные самопроверки бинарника.

`make build-core` создаёт сокращённый бинарник без нативных движков.
Для него явно выбирайте профиль `custom`; `standard` требует полного набора движков.

## Установка и пути сборки

`make build` по умолчанию пишет бинарники в `bin/`. Через `BIN_DIR` можно задать
любой относительный или абсолютный каталог; `build-core`, `build-dev`, `host-test`,
`evaluate` и `releasecheck` используют ту же настройку. При запуске каталог сборки
не требуется.

Чтобы установить Scout для своего пользователя:

```sh
make install
export PATH="$HOME/.local/bin:$PATH"
scout doctor
```

Один раз добавьте каталог установки в `PATH` вашей оболочки. Префикс по умолчанию —
`~/.local`; `make install PREFIX=/opt/scout` устанавливает бинарник в `/opt/scout/bin`,
если каталог доступен для записи. `DESTDIR` позволяет подготовить дерево файлов
для упаковки без изменения префикса установки. Установка копирует только бинарник Scout.

В шаге оболочки GitHub Actions можно собирать прямо в каталог, выбранный исполнителем:

```sh
make build BIN_DIR="$RUNNER_TEMP/scout-bin"
export PATH="$RUNNER_TEMP/scout-bin:$PATH"
scout doctor
scout scan --format json ./my-skill
```

Для последующих шагов также добавьте каталог в `GITHUB_PATH`.
Если бинарник уже собран, добавьте его каталог в `PATH` или укажите полный путь.

## Кеш и работа без сети

Подготовьте зависимости до отключения сети:

```sh
make deps native-deps
```

Следующие сборки используют их повторно. Кеш нативной библиотеки по умолчанию:
`~/Library/Caches/scout/native/` на macOS и `${XDG_CACHE_HOME:-~/.cache}/scout/native/`
на Linux. Путь задаёт `SCOUT_NATIVE_CACHE`. `make clean` удаляет три бинарника Scout
из `BIN_DIR` и временные данные `.work/`, сохраняя зависимости и установленные копии.
При очистке нестандартной сборки передавайте тот же `BIN_DIR`.

## Внешняя установка

Для нативных Go-команд на поддерживаемых платформах используйте ту же обёртку
подготовки зависимостей, что и Make. Запускайте её из корня репозитория:

```sh
go run -mod=readonly ./internal/dev/builddeps -- \
  go test -mod=readonly -tags=static_link ./...
```

Через `PKG_CONFIG_PATH` выберите доверенную YARA-X C API 1.22.0 с файлами
`libyara_x_capi.a`, `yara_x.h` и файлом pkg-config. Она нужна для платформ без закреплённого
готового пакета или при запуске команд в обход Make и обёртки.
Сборка из исходников описана в [документации C API](https://virustotal.github.io/yara-x/docs/api/c/c-/).

## Версия сборки

Для релизного архива без метаданных Git передайте тег или SHA коммита:

```sh
make build VERSION="$GITHUB_SHA"
```

Все цели сборки принимают `VERSION` и дополнительные `LDFLAGS`.
`scout version` показывает полученную версию. Тесты и приёмка описаны
в [руководстве проверок](validation.ru.md).

## Релизы через GitHub Actions

При push в ветку и в pull request запускаются линтер, core- и нативные Linux-тесты
с проверками гонок, целостности сохранённых измерений и границ адаптеров приложений.
Полная проверка macOS/Linux/Windows и сборка релизных бинарников запускаются по
версионному тегу или явно вручную.

Workflow **Scout release** собирает три полные нативные версии:

- `scout-vX.Y.Z-macos-arm64.tar.gz`: Apple Silicon, macOS 15+.
- `scout-vX.Y.Z-linux-amd64.tar.gz`: GNU/Linux x86-64, проверка на Ubuntu 24.04.
- `scout-vX.Y.Z-windows-amd64.zip`: Windows x64, проверка на Windows Server 2025.

Каждый архив содержит только `scout` или `scout.exe` в корне.
`SHA256SUMS` публикуется отдельно и содержит контрольные суммы всех трёх архивов.
Сборки macOS не подписаны и не нотариализованы; у Windows-сборки нет подписи Authenticode.

Сначала закоммитьте и отправьте workflow и исходники, затем создайте тег релиза:

```sh
git tag v1.2.3
git push origin v1.2.3
```

Теги `v*` с тремя числовыми компонентами версии (major, minor, patch) запускают автоматическую публикацию.
Теги вида `v1.2.3-rc.1` создают предварительный выпуск. Workflow выполняет нативные тесты,
проверки гонок, зависимостей бинарника и встроенные самопроверки. На macOS/Linux
также должна пройти проверка целостности сохранённых измерений. Правки исходников
не требуют замены исторических записей измерений. Упаковка использует именно
проверенные бинарники. Отдельная Go-команда `internal/dev/releasepack` создаёт
архивы и контрольные суммы средствами стандартной библиотеки Go.
Все три архива сначала загружаются в черновик релиза,
после чего он публикуется. Неудачную загрузку можно повторить, пока релиз остаётся
черновиком; опубликованные файлы workflow не заменяет.
Если релиз уже опубликован, workflow сначала побайтово сравнивает существующие
файлы с артефактами сборки, затем загружает только недостающие. Несовпадение
останавливает публикацию и требует нового версионного тега. Название, описание
и статус предварительного выпуска уже опубликованного релиза сохраняются.

Для пробной сборки выберите **Actions → Scout release → Run workflow**.
Ручной запуск сохраняет `release-assets` на 14 дней и не публикует GitHub Release.
Для публикации используется встроенный `GITHUB_TOKEN` с `contents: write` только
в задании публикации. Личный токен не нужен, если политики репозитория и организации
разрешают такую публикацию.
Пока первая версия продукта не выбрана, запускайте сборку вручную на ветке:
бинарники и архивы будут помечены SHA коммита без назначения версии продукта.

Windows-задание собирает YARA-X 1.22.0 из закреплённого коммита исходного проекта
`e27597f2c05e13fe1c2bb459781aef8899afc485` с Rust 1.95.0, его `Cargo.lock`
и набора инструментов GNU UCRT64 для CGO. Проверка релиза отклоняет внешние DLL YARA-X
и библиотеки среды выполнения компилятора, затем выполняет нативные самопроверки в изолированном окружении.
Автоматическая локальная подготовка зависимостей через Make по-прежнему работает
на macOS/Linux; Windows-сборка использует PowerShell-скрипты из `.github/scripts/`.
