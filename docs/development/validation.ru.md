# Проверки

[English](validation.md) · Русский

Запускайте команды из корня проекта. Полный набор требует
[нативных зависимостей](native-build.ru.md).

## Тесты

```sh
make test-core
make test
make race
make host-test
```

`test-core` проверяет сокращённую сборку и недоступность движков. `test` и `race`
проверяют нативные парсеры и сигнатуры. `host-test` требует Node.js и проверяет
адаптеры на тестовых реализациях SDK и настоящем CLI. В CI используется Node.js 24.
Тесты Go не требуют Python.

Тестовые цели Make используют `-vet=off`; линтер запускается отдельно.

## Бинарник и сохранённые измерения

```sh
make releasecheck
make acceptance
```

`releasecheck` проверяет компоновку, метаданные и нативные самопроверки бинарника.
`acceptance` проверяет целостность сохранённых идентификаторов входов, результатов повторного
сканирования, releasecheck и разобранных изменений наблюдений в `testdata/provenance/scout-current-review.json`.
Проверяется записанное измерение, без требования совпадения с сегодняшними исходниками.
CI нативной сборки выполняет эту проверку вместе с тестами текущего кода.

Правки кода и комментариев не требуют обновления записей измерений. Хеши исходников остаются
метаданными измеренной версии. Явная проверка `provenance verify --current-sources`
при необходимости сверяет запись с текущими исходниками. Новое измерение создаётся
через [команды учёта происхождения](commands.ru.md#source-bound-provenance), когда нужно обновить
сохранённые результаты. Входы в `testdata/` сохраняются после `make clean`.

## Линтер

```sh
make lint
```

Матрица по умолчанию включает core для `darwin/arm64`, `linux/amd64`,
`freebsd/amd64`, `windows/amd64`, а также варианты без CGO и с нативными движками на текущей платформе.
Каждый запуск включает тег `acceptance`. Матрицу меняет `LINT_PLATFORMS`.
Отдельные цели: `lint-core`, `lint-nocgo`, `lint-native`.

## Интерпретация результатов

Регрессионные тесты и провайдеры с заданными ответами проверяют поведение реализации, без измерения
качества настоящей модели или независимой точности детекции.
См. [измерения](evaluation.ru.md) и [проверки использования знаний](../reference/knowledge-runtime.ru.md).
Совместимость с реальными приложениями и целевыми платформами требует отдельной приёмки.
