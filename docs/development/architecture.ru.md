# Архитектура и границы доверия

[English](architecture.md) · Русский

Go API, CLI и MCP используют общий процесс проверки:

```text
operator options → bounded capture → immutable inventory
→ extraction/source maps → component graph → checks
→ optional semantic review → coverage/validation → sealed Run
→ policy evaluation → prepared report
```

## Захват и исходные координаты

Байты входа, имена, манифесты и инструкции недоверенны. Политику, провайдера,
учётные данные и сетевые разрешения задаёт только конфигурация оператора.
Проверка не исполняет обработчики, установщики и серверы проверяемого пакета.

Захват сохраняет неизменяемые байты и хеши инвентаря; непрочитанные записи остаются
пробелами проверки. Чтение относительно корня без перехода по символическим ссылкам не создаёт транзакционный снимок
файловой системы. Извлечение сохраняет исходные контейнеры и создаёт ограниченные
виртуальные дочерние объекты. Карты исходников хранят точные соответствия байтов,
а для нелинейных преобразований — охватывающую привязку к источнику.

## Анализ

Доверенный реестр выбирает парсеры и анализаторы. Языковые пакеты реализуют
`check.Analyzer`; общие неизменяемые факты позволяют не собирать наблюдения повторно,
сохраняя независимые лимиты и результаты правил. См. [поддержку языков](../reference/languages.ru.md).

Граф компонентов хранит декларации, ссылки и предполагаемую активацию в приложении.
Фиксированный план заданий и журнал результатов показывают пропущенную,
неуспешную и незавершённую работу. Каждый анализатор получает одно задание,
связанное с отсортированным набором подготовленных файлов; результаты по файлам
остаются в coverage. План не растёт как число пар «файл × правило».
Собранные доказательства сохраняются при последующих ошибках.

Семантическая проверка использует ограниченные фрагменты исходников и ссылки
текущего запроса. Гипотезы и оценки модели хранятся отдельно от статических находок.

## Публичные границы

Scanner владеет нативными ресурсами. `Close` прекращает приём работы и ожидает
активные вызовы. Run содержит наблюдения; отдельный доверенный `policy.Gate`
применяет политику. `report.Prepare` проверяет привязку результата и оценки,
создавая независимый снимок для всех форматов. См. [контракты API](go-api.ru.md).

Baseline применяет исключения оператора без удаления наблюдений и закрытия пробелов.
Загрузка, сетевой поиск уязвимостей и передача исходников имеют отдельные разрешения.
Нативные движки работают внутри процесса с кооперативными лимитами и отменой.

Записи измерений учитывают локальный нативный код и заголовки наряду с Go-файлами
и встроенными материалами, включая неактивные варианты сборки. Хеши описывают
измеренную версию. Обычная приёмка проверяет сохранённые результаты независимо
от сегодняшних исходников; их совпадение проверяется только явной командой
`provenance verify --current-sources`.

## Границы пакетов

`report` не зависит от среды выполнения сканера. Языковые пакеты не импортируют друг друга
и общий реестр анализаторов. Адаптеры пользовательских команд и инструментов разработчика разделены.
Эти границы проверяет `internal/architecture`. См. [структуру репозитория](layout.ru.md).

Код исполнения использует `Analyzer`, `Match`, `Trace` и `Result` из пакета `check`,
владеющего контрактом проверок. Функции привязки реестра нужны только при подготовке
исполнения. Отображаемые категории файлов принадлежат `syntax/filetype`; построение
доказательств не обращается к реестру анализаторов. Словарь событий хуков остаётся
в `hookpolicy`: функция `KnownEvent` проверяет принадлежность, не открывая доступ к изменению таблицы.
